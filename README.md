# 以撒的竞合：冲 · 慎

*The Bidding of Isaac: Rush & Restraint*

一款围绕 **20 人共同市场、秘密报价、资源管理和连续道具构筑** 展开的短局博弈游戏。当前可游玩原型采用 **1 名真人玩家 + 19 名 AI**，全部对局与 AI 逻辑在玩家浏览器中执行，不需要业务后端。

> 本项目是非官方同人创作，与 *The Binding of Isaac* 的作者、发行商及相关权利方无隶属或认可关系。当前26件道具均已使用用户提供的收藏道具／饰品／掉落物图片，见 [图标映射](./道具图标接入_v1.md)。

## 单文件 HTML 离线验收

改完代码后执行一次，不需要持续启动开发服务：

```powershell
Set-Location -LiteralPath 'D:\The Bidding of Isaac\web'
npm run build:offline
```

生成 [以撒的竞合.html](./web/dist-offline/以撒的竞合.html)。在文件夹中用浏览器打开该文件；分发时只发送这一个 HTML，无需附带 `assets`、Node.js 或 Docker。固定入口每次覆盖同名文件，同时生成带版本／构建标识的分发HTML及清单。产物不进入Git，完整交付使用 `npm run build:release`，见 [交付说明](./新手教程与版本交付_v1.md)。

这不是界面截图，而是使用正式入口与规则的完整客户端。代码改动后需要重新构建；浏览器允许时刷新恢复本局，也可从设置读取JSON存档。正常 `npm run dev`、`npm run build` 和 Docker 流程不变。

构建门禁、普通HTTP网页视觉复验与直接file离线验收是三种不同证据。已允许内置浏览器访问临时本机普通网页进行复验；直接file被工具拦截时不换浏览器或代理文件绕过。后续按“修改源码→测试→构建→网页复验／用户离线与游玩反馈→修正”推进。详细记录见 [离线构建与验收](./离线HTML构建与验收.md)。

## 本地 Docker

完整交付包可在 `web` 目录执行 `npm run build:deployment` 生成：同版本网页、离线下载、文件证据和直接复制已验证网页的镜像上下文。未提交代码可生成开发预览，但严格远端发布会拒绝；不会因执行构建命令自动上线。

仓库已经包含多阶段Dockerfile、Compose端口映射与Nginx配置；本地版本交付与T11发布准备已实现，首次远端／容器运行验收仍待执行。CI默认只校验，Pages／镜像／草稿Release仅手动触发，见 [发布准备](./云发布与分发准备_v1.md)。当前以电脑端优化为主，移动端明确后移。

在仓库根目录执行：

```powershell
docker compose up --build
```

随后访问 [http://localhost:3000](http://localhost:3000)。容器负责分发静态网页；对局、AI 和随机状态仍在浏览器中执行。浏览器允许时自动保存并在刷新后恢复对局；可携带的JSON文件用于跨地址／浏览器继续游戏。

停止容器：

```powershell
docker compose down
```

## Git 工作方式

0.2.13当前功能基线是`codex/offline-html`上的`8ea001f`，不是已经合并main或已发布的标签。阶段收尾仅提交并推送当前分支；不自动合并、打tag或部署。后续底层重构先确定范围和旧数据迁移，经典模式作为行为对照，见 [交接清单](./0.2阶段总结与重构交接.md)。

`main` 分支保持可运行。功能开发使用短期分支，并在合并前运行测试和生产构建；发布标签采用 `v0.x.y`。仅文档整理不得顺带修改游戏规则或参数。
