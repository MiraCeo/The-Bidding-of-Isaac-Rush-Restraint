## 三、下一批实施顺序

1. **先做当前语料与独立输出。**经典、生存及混合／多根多分支三类，从当前生命周期产生真实原因事件模板，再合成不同身份放大。保留完整key、parent、authority、阶段、时间及激活边界；记录构成和生成方法，明确合成条数不等于真人实玩局数。基线清理前旧材料只作独立恢复／清理边界测试。
2. **先测不优化。**从空、小档、256、2048、4096、8192、12288至16384及超界探测；较大构成可能先撞字节预算，如实记录拒绝，不能强行造一个能保存的模板宣称普遍容量。
3. **组合预算。**同时考察历史200条、32KiB其他扩展、完成凭据增长至8192的组合，以及单根长链／多根／分支差异；记录模块、整档、压缩容器、pending及配套对局大小，不能只测成就对象。
4. **分开计时。**读取／解码核验、成就投影、单次追加、同一事实重复、批量待保存、当前档案导出／预览／恢复及gzip往返。记录原始样本、中位数及极值；同一环境对照，区分首次与重复、缓存冷／热，说明样本次数及内存测量口径。
5. **失败与正确性同时核对。**1MiB及再多1字节、模块／条数限制、未知／损坏编码、配额异常、同源冲突模拟、重复确认、原文保护、pending重试和配套恢复回滚。核对每枚真实进度、独立达成时间、角色权限、父分支及去重结果，不只比较总完成数。
6. **依据数据决定最小优化。**输出瓶颈及可复验结果后再选择实现；若触及编码、上限、去重证据或继承边界，单列方案，不因“优化”自动改规则。实现后同环境同构成复跑，并保留优化前原始报告及失败样本。

新入口`npm run report:ledger:corpus`已使用独立`web/work/v05-closeout-ledger/corpus-随机串/`，排他写入，不覆盖`v050-ledger`或任何旧运行。现阶段只生成0／64／256规模的有效性与体积样本；短路径保留，已另补25房／5层的57单元样本；大规模容量与成本采样走独立`report:ledger:capacity`入口，见[基线记录](../记录/0.5末期账本容量与核验基线.md)。本轮准备证据另在`web/work/v05-closeout-prep-20261016/`，不混进下一批测量结果。
