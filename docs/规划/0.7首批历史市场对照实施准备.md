## 二、首批最小范围

目标：让右侧栏提供可读的历史参考，而不是重复一份当前报价预览。

1. 右栏以“市场参考”为主：**本局、同层、最近三个已结算房间**，按房间位置从近到远列出；不足三房就展示实际数量。
2. 每房保留房间位置、共同基准线、A／B各自的历史高价名额边界；需要查看具体公开行动时复用现有复盘入口，不默认再放一张大图。
3. 当前个人市场影响降为摘要，A／B仍分别表示；理论竞价能力与当前名义／实际／市场／计分口径保持，不拆成新任务系统。
4. 首房／换层无同层历史时显示紧凑空态。全场观望、某组无人参与或没有高价名额时显示缺值原因，不填0冒充边界。
5. 本批先不做跨层折算、跨局统计或趋势预测；上一层参考如后续需要，再按候选总表单列来源及公共资金尺度，不混进默认三房列表。

建议初版仅用三行历史记录及A／B数值列，保持现有暗色／金色层级与右栏宽度；选中当前目标的对照更清晰即可，不预先加复杂筛选、全屏市场页或新的交互系统。

## 三、必须先固定的数据口径

- 历史高价边界 = **对应组真实高价名额中的最低市场等价**，包含扰乱占位；它不是最终发奖名单中的最低价格，也不是保证获奖价。并列、名额不足、奖励销毁／重复等仍以原结算事实为准。
- 市场等价只对照对应组的历史高价边界；计分等价对照历史共同基准线／合作区。不能把Steam实际扣款、名义金额或两组报价总和混进市场排序。
- 合作区半径使用历史房间所属层的公共基础资金与规则比例，不用当前余额或角色个人层初始资金。基准线相关道具的计分修正必须说明历史条件，不能暗示本房共同基准线已知。
- 双行动保留每组独立样本；A／B不能合并为一个边界或平均值。扰乱、观望、无可用报价如实表示，不把历史参照计算成概率或推荐值。
- 数据只来自当前对局已经公开的原始结算。其他玩家本房待提交／秘密行动、未来奖励、其他对局与AI合并历史摘要均不能作为来源。

## 四、现有源码接点（已核对，不代表已改动）

| 范围 | 可复用接点 | 首批处理 |
| --- | --- | --- |
| 经典已结算记录 | `lib/ui/replay-record.ts` 的 `ReplayLog.rooms`／`ReplayRoomRecord.settlement` | 在经典父级从当前session回放中选择已公开房间，不能只依赖当前game的空结算 |
| 生存已结算记录 | `lib/game/survival-session.ts` 的 `roomRecords` | 只选当前局同层已完成记录，不混用其他模式／只读文件 |
| 组边界与市场点 | `lib/ui/replay-market.ts` 的 `replayMarketModel` | 已有A／B cutoff包含扰乱名额，可提取只读小模型，保留对应组与原始单位 |
| 现有右栏 | `components/game/market-impact-preview.tsx` | 保留个人草稿隔离；历史通过显式、裁剪后的只读模型输入，不传秘密turn集合 |
| 页面接线 | `classic-game-app.tsx`／`survival-game-app.tsx`／`room-prototype.tsx` | 分模式提供合法来源，避免子组件自行读取全局存储或内部AI状态 |

优先使用纯选择／派生函数：输入已结算记录＋当前层房位置，输出最多三条轻量记录；不修改原对象，不写storage，不新建常驻账本或格式字段。现有记录足够时不升级schema或重新执行游戏／AI来“重算”历史。

## 五、实施顺序与验收点

- [ ] 先完成只读历史模型：覆盖空历史、同层不足／超过三房、换层、A／B不同边界、并列与扰乱占位、全场观望／缺值；对输入做不可变性断言。

- [ ] 再替换右栏层级，保留收起／展开偏好、键盘和无报价状态。进行900～1920 PC宽度与长数值／双行动核对，不让辅助栏挤压输入和确认操作。

- [ ] 浏览器可用后实机核对已公开记录与显示数值；不可用时明确保留视觉待验，不旁路控制或用静态检查冒充实际页面。
