## 界面要求与实现

- 深棕／金色紧凑收藏页：总览完成数／完成率／角色数来自已保存档案，不受列表筛选影响。
- 列表仅独立图标、名称、短条件与状态／必要进度；一次性target=1不显示0/1条。已有累计及单局目标保留简短进度，列表封顶目标、详情显示真实记录值；单局进度仍为已记录最高，不冒充当前连续数。
- 每项采用不同的本地代码图标，徽章轮廓辅助六分类识别，已完成与未完成兼有亮度及文字／符号区别，不依赖色彩单独传达状态。不复制原作美术，不加载远程资源。
- 全部与六类切换、全部／已达成／未达成筛选，支持名称或编号搜索；编号／最近达成／目标比例进度排序，平局按编号稳定排列。无结果可清除筛选，保留列数偏好。
- 使用现有已安装Base UI Dialog：模态焦点、Escape／关闭、返回原按钮；弹窗不展开网格。包含编号、原完整条件、适用模式、特殊判定、真实进度、达成时间与角色关联，不修改判定来源。
- 根据成就容器实际可用宽度排列：不足620px为1列、620～979px默认2列、980px起默认3列；手动1／2／3列是上限，窄容器优先可读性。内容最大1200px，不按整窗宽度误判侧栏空间。
- 仅显式列数选择写独立显示偏好键`bidding-achievement-layout-v1`，值`{version:1,columns:"auto"|"1"|"2"|"3"}`。不属于玩家档案、续玩或完整库；读取不写入，失败只影响偏好持久化，当前页仍应用。诊断按偏好分类，既有游戏显示设置保持独立。
- 五角色卡片简化，区分默认／成就解锁／手动授权／未解锁；前置按钮直接打开详情，不要求清除当前筛选。不因授权伪造前置进度。角色授权时间保留，保存后达成提示仍由原事务链路控制。

### 实现前必须固定的边界

1. 编号和分类：保持六大类，不先占用新ID或变更现有角色前置；新增六项是否全部纯收藏，正式纳入时明确。
2. 新增项的激活／追溯：是否全部从纳入后的新正式事件开始；已有0.5完成凭据、正在进行对局、旧growth日志／明确恢复快照各如何划界。现有“不回溯0.4／重复导入不记账”不能自动等同“新六项可以扫旧0.5历史补发”。
3. “和而不同”的资格与发放边界：合作排名落选但由最高价／幸运脚实际拿到同组奖励时是否明确不满足；同组资格被效果消除不能冒充合作落选。双组某组落选、另一组有奖励时按单组还是整房判断。
4. “失之交臂”的名次集合与发放边界：现行没有独立的“高价区”布尔事实，“高价竞争区”的范围仍需定义；第N＋1是含扰乱的正式占位排序还是仅正常竞拍排序；其他途径获资格但奖励被消除是否排除；双竞拍是分组分别判断还是整房失去全部道具。
5. 两项允许同房同时触发这一点已明确。仍须确认是同一份行动可同时满足，还是双行动分别满足；这不是擅改市场名额的理由。

### 最小技术增量（建议，未开发）

- 前四项新增正式终局事实、角色完成集合及准确来源；当前classic成长无final阶段、survival final只含存活／最高难度／淘汰层，紧凑旧值不能事后推导冠军或角色集合。按显式新事件／schema演进，保持原schema1／2完整去重，不按指标相似性替代权威身份。
- 后两项建议在权威结算时旁路保留“合作落选”“实际高价第N＋1”的原因证据，再与资格／真实发放关联；不改变tie-break抽样次数、排序、名额或扰乱空位。需要原始真实次序的地方不能重新抽随机数。
- 继续成功事务后记账；重复权威事实、只读／恢复／回退、失败pending重试、跨页代次守卫全部保留。新增成就版本迁移不得给旧30项重复改达成时间。
- 必需用例：经典并列第一、低难度生存冠军／非冠军存活、五角色重复／淘汰／手动授权、两种排序与同价真实次序、扰乱占位、其他奖励路径、尾巴消除、更多选择、双行动同房双触发、旧档激活边界与完整失败回滚。
