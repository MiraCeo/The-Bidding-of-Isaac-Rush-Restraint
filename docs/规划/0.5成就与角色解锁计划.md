## 二、确定产品范围

- 30项／6分类，A02及E01～E05共6项解锁前置，其余24项纯收藏。不追加已删除候选。
- 默认以撒；游魂=A02＋E01，阿撒泻勒=E03＋E04，伊甸=E05，雅阁和以扫=E02。
- 新老玩家首次启用0.5均按相同角色规则；一键解锁仅改变权限，不更改成就或计数。正常重载不重新锁定合法权限。
- A～E共享经典／生存正式模式累计；单局连续／复合条件不跨局拼接。F仅生存，只有F02指定最高AI难度。不计教学或AI个人成就。
- 按进房／房间／层末／终局有效结算即时入账，保存成功再提示；放弃不撤销，纯旧历史不回溯。
- 保持正式竞拍、道具、AI、资金、随机流和生存规则。不加成长货币、永久对局加成、联网、新赛制或移动端。

UI隐藏策略、页面入口、提示动画和展示形式仍单独讨论，不据本计划自动建设界面或大型任务系统。

### 不可省略的解释规则

1. 正常竞拍失败按市场资格判定阶段，而非最终库存或更多选择删除后的entitlements。利用已有名额及原因事件恢复资格含义，不重跑奖励随机。
2. 更多选择destroy足以证明双资格后随机舍弃；尾巴destroy／duplicate明确记录effectItemId，不能混用itemId（它可能指受影响奖励）。
3. 最高价／合作／幸运脚可同时列入sources。B01与B02允许多资格同时成立；D05需要不存在原最高价与合作名额资格，且实际交付。B02按机会，E05按copies。
4. 扰乱轮空按group＋playerId＋slotType匹配赎回；同组另一名额成功、同组仍发奖，不代表本名额没有轮空。
5. D04使用评分时强化additive_score与当时持有数量，不用最终余额；多件普通+5不能误当一件强化+20。D06比较名义报价与prepared playersBefore中的资金。
6. E02／E04检查真实房间awards；初始装备不计获得，但后续真实效果可计。E03检查房型boss而非道具池。E05检查原treasure奖励的hidden属性。
7. F03比较存活名单中的权威survivalScore，不比较整局累计、新增分或显示精度舍入后的值；所有并列最低存活者都满足。
8. F05只在整场正式终局确认，且真人淘汰本身必须是允许统计的新事件。早期团灭是实际最后淘汰时允许F01与F05同时成立。

## 四、最小新增数据及唯一明确的评分缺口

### 4.1 成长模块（初始字段候选与当前后台实现）

第二批实际采用achievementRegistryV1有界紧凑凭据与manualUnlockAllAt，累计、达成时间、分支状态和角色权限从凭据推导，不重复保存一份易矛盾的累计。模块上限2048条／896KiB，整档1MiB不变；旧history／完成凭据上限不变。下表保存最初设计用途，具体字段以第二批实现记录为准，正式生命周期／检查点上下文仍待接入。

建议以独立有版本的成长模块承载，并与现有achievements／characterUnlocks在一次档案候选内一致更新：

| 数据 | 用途／约束 |
| --- | --- |
| schemaVersion、catalogVersion、activation／migration标记 | 识别受支持的0.5状态并幂等初始化；不是凭档案空不空猜旧玩家 |
| 正常竞拍失败累计 | A01／A02共用，不与A03混用 |
| 最高价成功机会累计、利息收入累计、隐藏奖励件数累计 | B02／D03／E05；安全整数与真实事件金额，不从旧统计回填 |
| 成就进度及achievedAt | 已达成保持，不因活动局连续数清零而撤销；展示目标与原始累计可分层 |
| 角色权限与授权原因 | 区分成就组合／一键解锁，不能用手动角色授权伪造成就完成 |
| 活动局成长上下文 | 迁移排除边界、结算来源、同局连续／复合状态或可重算范围、F05待确认淘汰 |
| 有界处理凭据／事实前缀证明 | 进房、房间、层末、终局分别去重；不能仅存最后房号或终局receipt |
| 待保存候选的重试所需信息 | 不提前推进已提交边界；保存失败可从保留的合法事实安全重试 |

未知ID与旧扩展数据保留但不执行；损坏／未知版本成长模块不得当成空模块重新迁移。旧0.4可能保留的预留成就／解锁字段不是0.5奖励证据，初始化需保留其历史扩展，不据此开放角色。

同局状态可以存小型状态，或从合格有界事实重算；不同时复制一份完整回放进入档案。A03按整房结果先决定清零／增加，再检测达标，不逐份处理混合结果抢先发奖。

当前档案正文1MiB、最近历史200、完成凭据8192是现有不同边界；成长凭据限额不能直接冒用8192。实施前测量普通局、35房、生存AI续赛、多分支及长期累计的体积，再固定独立有界策略。到上限应保留原资料并明确未新增入账，不自动删凭据或归零；不引入自动清库。

### 4.2 E01精确的未清零应得分

第二批已采用不改v5字段的评分WeakMap旁路，并在独立成长账本保留真实事件的四位证据；不是重算旧回放或凭旁路存在判断来源。旧复制／无证据对象仍不猜测，正式控制器需在回放复制前捕获。下文为初始工程候选，不代表必须把字段塞进旧v5正文，最新实现见第二批记录。

现行calculateTurnScore保留clear_score原因，但清零后score=0；action分项已舍入，再相加乘multiplier不能保证等于原未清零房间分。

工程候选是增加scoreBeforeClear：用评分阶段现有未舍入subtotal与已发生multiplier，按同一正式四位积分精度取整，表示未应用清零且未发生后续新获心脏追溯的应得分。E01需要该值>0并有永恒六面骰clear_score；C07不加这个限制。字段只记录诊断，不多掷骰、不调整计算顺序或原score。

必须同时设计经典紧凑事实、生存事实、严格校验、检查点重建、压缩往返与旧v5读取边界。旧原始hash基线保留；如果诊断字段使新状态结构不同，应区分权威行为与新诊断契约，不能从当前待审实现覆盖历史golden。无该证据的旧已发生事件不补发E01。

其他主要事件目前已够用；不要为了成就增加第二套奖励、重复经济效果或新随机择优。

## 五、入账与恢复链路

### 5.1 结算阶段

| 阶段 | 判定／更新 |
| --- | --- |
| 新进房经济结算 | D01／D03；保存成功即入账，未报价便放弃也保留 |
| 新房间结算 | A～E对应条件／累计及单局状态；新取得奖励才做获得型判定 |
| 新层末结算 | F01／F03／F04；保留真人合法新淘汰供F05确认 |
| 新正式终局 | F02／F05；现有完成统计仍按原终局口径登记 |
| 读取／预览／重建／只读回放／整库恢复 | 不产生新入账单元 |
| 明确替换档案 | 恢复已有快照，不按内容重新判定或补发 |

处理顺序：权威结算完成→取得明确来源的新事实→校验成长资格／迁移边界→纯指标提取→事实去重→构造计数、成就、角色权限与凭据同一候选→严格校验及容量核对→保存→通知／提示。

若同一步还有完成统计，统计与成长应在同一档案候选中更新，避免统计成功而成长丢失；两者去重逻辑仍独立。单次profile写入不代表所有对局键原子提交，也不代表跨页面全局锁。

### 5.2 去重与失败

- 去重须绑定模式、同局上下文、结算阶段／位置及权威事实；排除导出时间、界面版本与单纯重建来源变化，保留不同真实分支。不能靠每次导入生成新领取身份。
- 共同旧事实／已处理前缀不能重复累加；回退检查点、同局分支及跨页交错需要专门用例。完成模块的完整终局SHA可以参考，不能替代逐结算凭据。
- 保存失败保留旧档案和合法待处理事实，不显示已达成，不提前推进提交边界。重试只提交一次；迟到结果和旧预览不能覆盖其他页面新资料。
- 当前重读原文后最多重算三次的机制可以复用，但不是CAS。工程实施需先提交跨页序列化／冲突拒绝策略及能力不足处理，验证两页同时入账／恢复；不能把全量测试通过宣称为已解决全部并发。
- 因成就保存失败不能改变AI、报价、淘汰或随机结果。对局与成长各自保存状态如实提示；不能默默清空或自动补历史来解决失败。

## 六、迁移与协议设计

### 6.1 玩家档案

初次识别确实没有0.5成长模块的旧档案时，保留原历史／累计／扩展，初始化新成长计数和默认以撒权限，写入显式迁移标记。已支持的0.5模块按原状态读取；未知或坏模块保留原文并报告，不能再次默认迁移。

一键解锁只更新角色授权；成就组合使用同一目录定义，不在选角页和成就页各写一套规则。新局UI与开始入口双重校验；旧角色续玩、教学体验和AI池不跟随人类权限缩小。

### 6.2 旧进行中局

载入旧局后建立升级排除基线，分别识别此前已发生的进房经济、房间、层末和终局事实。尤其是旧room_action的进房钱已结算但竞拍未结算：旧进房不计，新竞拍可以计。

A03／C07不借旧上下文；F04只认正式前三层全部合格新通过事件；F05要求新淘汰，不能借升级后的终局确认补旧淘汰。F02可以由正常继续旧进行中局新产生的真人最高难度存活终局达成。纯旧完成局、旧回放和旧累计不发奖。

0.5局刷新／续玩要保留处理边界，而不是当作旧局重置。不同来源、跨页面和分支不能互相覆盖边界；读档重跑历史命令只用于核验，不生成奖励。

### 6.3 主动档案替换

保持明确替换、不自动合并。恢复更早0.5快照允许成长／权限回退，按快照处理；明确恢复0.4档案则保留其旧成绩、按新体系默认仅以撒，不补旧奖励。普通重载不会回退合法状态。

恢复不是发奖触发；不保证在全部档案回退后仍有永不回退的独立外部领取总账。当前档案凭据与检查点边界仍用于排除重建旧事件。保留原文变化守卫、明确替换、取消及失败不覆盖语义。

### 6.4 格式选型待工程验证，不是待定产品规则

当前v5检查点与事实严格拒绝多余字段。成长上下文若要跨文件／来源继续，必须有显式保存、校验与恢复设计；不能只放React ref或只根据导出版本猜历史结算版本。

实施前提交字段位置、schema／版本、旧0.4 v5续玩兼容、两模式配套备份匹配与错误保留方案。可以评估有界v5扩展或新版本，但本轮不预定具体升级号、不修改currentFileVersion。不重新引入v2／v3／v4读取，也不把容器1、档案1、对局5、库schema1混成一个版本。

## 八、必要防回归与交付标准

### 产品判定

- 30个唯一ID，分类数3／4／7／6／5／5，6个解锁前置，24个纯收藏；删除候选不出现。
- 正常失败退款、双败+2、混合结果清零、观望／扰乱保持、更多选择和尾巴消除不误计失败。
