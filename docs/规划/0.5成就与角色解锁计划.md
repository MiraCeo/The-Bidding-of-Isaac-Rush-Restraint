# 0.5成就与角色解锁计划

日期：2026-10-14；性质：规划草案／实施输入，尚未启动0.5代码。应用当前仍0.4.11。本页保存已讨论的计划；首批条件、默认角色、解锁关系、难度门槛和回溯范围尚未定稿，不因为文档落盘自动锁角色或发奖励。

## 一、定位与范围

0.5提供可靠的长期成长闭环：完成对局→累积目标→达成成就→记录／角色解锁→档案备份与恢复。首版以小而完整为目标，不同时增加成长货币、永久资金／积分加成、道具扩池、联网或AI／赛制大改。成就／解锁主要改变局外目标和新局选角，不改变正式对局的权威规则。

### 已确定与建议分开

- 已确定：成就与角色解锁留0.5；0.4现有功能与整理收口，未验收的分发范围继续单列。
- 建议：首批10～15个目标、终局统一判定、奖励先限徽章／角色、保留可识别旧玩家已有角色体验。
- 待定：具体名称／条件／次数／分数、默认开放角色、各角色解锁关系、最低难度、旧档案与无资料老玩家处理、历史回溯。不能把候选方向写成产品已经定案。

## 二、复用0.4基础

| 现有模块 | 0.5用途 | 尚需补齐 |
| --- | --- | --- |
| 独立玩家档案 | 保存成就进度／达成与角色解锁 | 专用模块语义校验、版本／启用状态 |
| 完成登记／事实去重 | 避免刷新和重复恢复累计 | 成长处理与统计登记区分，保存／重试一致性 |
| 累计统计 | 完成、冠军、存活、角色／难度分组 | 目标条件映射与回溯策略 |
| 对局完整事实 | 单局行动／构筑挑战 | 只取真人已发生事实的指标提取 |
| 进度中心 | 成就展示及摘要 | 分类、筛选、详情和反馈 |
| 档案备份／恢复 | 携带成长数据 | 明确替换／取消／失败与新模块版本核验 |
| 五角色选角 | 新局限制、说明与解锁提示 | UI与开始新局入口双重校验、旧局不受影响 |

现有achievements／characterUnlocks只是预留字段，当前不执行条件或奖励。当前模块completionRegistryV1的receipts在重复登记时直接返回，不可简单在其返回后附加成就代码并假定每条旧事实都经过成长判定。

## 三、首批成就方向

| 类型 | 候选方向 | 证据来源 |
| --- | --- | --- |
| 入门 | 首次完成经典／生存 | 正式终局登记 |
| 累计 | 完成若干局、获得若干次存活 | 独立累计，非最近200条历史反推 |
| 成绩 | 经典冠军、生存存活／榜首 | 权威排行／存活及冠军语义 |
| 角色 | 指定角色完成目标 | 真人角色与终局事实 |
| 构筑／挑战 | 道具组合或特定行动条件 | 真人实际参与房间、库存／事件 |

计分目标必须按模式及必要难度区分，门槛根据实际分布制定，不把经典与生存的原始分数直接比较。首批不以大量重复刷局目标填充，不从旧摘要推断隐藏行动或库存。

### 触发时机建议

首版统一在正式终局判定。局内可以展示本局条件已满足、等待结算，但不提前当永久达成；所有奖励先构造档案候选、保存成功后显示已获得。

生存真人提前淘汰时：行动／构筑只读取真人实际参与房间，冻结成绩与淘汰层；AI之后获得的道具／分数不算真人。完成类目标等AI结束整局再登记；难度读取该局已保存的难度，不读当前选角设置。

## 四、角色解锁

- 成就是目标，解锁是权限，分别建模；角色条件引用明确条件／成就ID，不在两个页面各写一套判定。
- 未解锁仍显示名称、特点、初始道具、条件和当前进度，不能只留灰按钮。
- 新局开始入口再次校验可选性，不能仅依靠按钮禁用。
- 已有续玩存档和历史回放保持原角色；AI角色池不跟随玩家档案缩小。
- 独立教学可体验角色，但不登记正式成绩／解锁。
- 可识别旧档案／存档玩家建议保留此前角色使用资格；新玩家默认角色尚未决定。没有任何持久资料无法可靠识别老玩家，需明确过渡策略，不简单用档案是否存在猜身份。

## 五、界面建议

主导航仍为游戏／排行／进度／设置／规则。进度新增成就分类，提供全部／未完成／已完成及类型／模式筛选；显示条件、当前／目标、达成时间与关联角色奖励。角色信息在成就详情和选角页关联展示，不另加主导航。

总览只展示少量最近达成与接近完成目标；达成提示可关闭、不阻断游戏。刷新／返回不反复弹旧成就，失败不假装已领取。页面继续复用0.4品牌、标题、内容宽度与返回结构。

## 六、数据与恢复

### 登记链路

已验证终局→真人指标提取→规则判定→完成／成长去重→统计、成就、解锁同一档案候选→校验并保存→通知与提示。纯判定器不运行AI，不调用UI和存储，不改变随机流。

分别回答这局是否计入统计、是否经过成长处理、新规则是否允许回溯。新规则不能靠重复导入让旧统计再次加局；也不能把旧完成receipt误当所有未来成就都处理过。按启用／规则版本处理，未知ID／扩展数据保留但不随意解释执行。

| 操作 | 建议语义 |
| --- | --- |
| 正常完成正式局 | 按条件登记 |
| 恢复未完成局后继续完成 | 结合来源与同一完整事实去重处理 |
| 重复刷新／恢复已完成局 | 不重复累计或领取；失败待处理可安全重试 |
| 只读导入／查看回放 | 不新增奖励 |
| 浏览／恢复完整回放库 | 不逐份发奖 |
| 恢复玩家档案 | 恢复已有成长数据，不再次按内容发放 |

保存失败保留原档案并明确待处理／重试状态，不能统计成功但奖励丢失、或失败却显示已获得。原预览变化守卫、明确替换、取消与迟到结果隔离继续保留；多页同时完成／恢复须增加回归，不宣称单键写入就是全局锁。

### 回溯与容量

可考虑用可靠已登记累计初始化有足够证据的累计目标；旧历史最多200条，缺完整事实时不猜构筑／报价挑战。首版不默认扫描整库发奖。

档案当前1 MiB、完成凭据8192条；不把每局完整回放复制进档案。只存必要结果、聚合和有界凭据。是否升级模块／档案格式按字段语义与实际体积决定，不先承诺所有格式完全不变，也不无依据大改对局v5。

## 七、实施顺序

| 批次 | 工作 | 验收 |
| --- | --- | --- |
| P0－1 | 目录、条件／奖励口径、旧玩家／回溯规则 | 条件明确且能由现有事实证明 |
| P0－2 | 纯指标提取／判定器、成长档案模块 | 同输入同结果、重复不增、严格校验及坏数据保留 |
| P0－3 | 两模式终局／保存／失败重试接入 | 淘汰冻结、来源隔离、档案一致性 |
| P1－1 | 首批成就与进度页 | 条件／进度／时间／反馈准确 |
| P1－2 | 角色解锁与选角 | 新局双重检查、旧局／教学／AI隔离 |
| P1－3 | 备份恢复、旧档案与实际试玩 | 数据不丢、不重复发奖、范围明确 |
| P2 | 门槛调整、展示细化、更多目标 | 依据真实体验，不无限刷局或扩大功能 |

先做判定与可靠保存，再做展示，最后接角色限制。实施批次不是已经发布的版本号，不预定日期或自动推进0.5代码。

## 八、首版完成标准

两模式可正常达成；条件／进度／时间／奖励可解释；重复恢复与刷新不重复领取；生存AI续赛不污染真人成长；解锁可用于新局且旧局不受限；备份／恢复保留成长；旧玩家策略明确；正式AI、斩杀线、计分与随机行为保持。
