## 一、0.5 的已确定产品原则

1. **成就用于记录游戏经历。** 指定的低门槛成就负责解锁角色，其他成就仅供收藏与挑战；不因此增加永久资金、得分倍率等对局优势。
2. **全部玩家在 0.5 启用解锁体系时，统一从“默认仅开放以撒”开始。** 不为 0.4 的既有玩家保留“历史版本全角色可选”的特权。原因是此前版本几乎没有对外分发，且 0.5 本来就提供**一键解锁全部角色**的途径。
3. **一键解锁全部角色只改变角色可用状态，不完成成就、不补加统计进度。** 成就完成状态与角色可用状态独立保存。
4. **不回溯旧历史。** 0.5 之前完成的对局、旧回放、旧累计统计不用于补发成就；0.4 进行中存档在 0.5 继续游戏，只认升级后新发生的有效结算事件。
5. **基于真实权威结算事实判定。** 尤其是道具触发原因、竞拍资格、实际道具发放、淘汰与存活，不得只凭最终数值倒推。
6. **不修改原游戏机制来迁就成就。** 必要时补充最小范围的事件或计数信息，不能擅自重排竞拍／道具结算顺序或引入复杂运营成长系统。

## 三、判定实现时需要特别保持的一致性

### 3.1 A03 连续失败的结算口径

- 跨局累计失败用于 A01/A02；同局连续失败用于 A03。两类计数不能混用。
- 屏障退还资金**不改变竞拍失败这一事实**。
- 观望、扰乱属于非正常竞拍行为，对连续失败数**保持不变**；换局才重新开始单局连续计数。
- 同房双竞拍的两个结果作为同一房间的一组结果处理：**双败 +2；任何一笔成功则清零**。因此，例如上一房已连续失败 4 次，本房一成一败，不得先因内部处理了“败”而授予 A03，再用“成”清零。
- 若工程实现中存在可复用的稳定行动序列，也必须满足以上**对玩家可见的结果不依赖 A/B 处理次序**的要求。

### 3.2 资格、次数、件数不能混为一谈

- **资格**：同组最高价与合作区资格可并存，同一份实际奖励可以同时推进 B01 与 B02；同组仍只按原引擎规则发放道具。
- **成功获奖次数（B02）**：按实际交付过道具的、具有最高价资格的**奖励机会**计数；尾巴复制不额外增加成功机会次数。
- **实际取得件数（E05）**：按照符合隐藏问号奖励条件的**真实发放道具数量**计数；复制两件可记两件。
- **幸运脚（D05）**：只在它是获得资格的必要原因时成立。与已有最高价资格重叠时不成立。
- 「更多选择」引起的 A/B 两组有效正常竞拍，应分别记录资格和结果；但奖励资格、随机舍弃和最终交付仍按原规则，不为了成就创建额外奖品。

### 3.3 事件触发与最终状态不能互相代替

- C06、D04 可以在后续被其他效果清零后仍成立，因为所要求的翻倍／加分曾真实发生。
- E01 要求永恒六面骰把**原先大于零**的本房积分清零；原本就是零分、只触发零分赋值则不满足 E01。
- C07 是两种**特定效果各自触发**的组合条件，可同房完成；判断时以效果触发记录为据，而不是以最终零分倒推，也不强制第二种清零必须再次造成正数损失。
- 不得通过库存快照变化推测道具是否是开局自带还是房间新获；两类事件需有可区分的来源。

### 3.4 生存结算

- F03 比较的是**当层淘汰结算后的存活者**，不是所有参赛者；出现并列最低分时，相关存活者都满足。
- F05「功亏一篑」仍以**实际整局中最后一次淘汰结算**为准。该结算是否为最后一次，应以正式生存流程的终局事实确认；如事前无法确定，可等终局确认后发放，不得为了提前判断硬编码一个固定层数或改动淘汰机制。
- F02「逃出生天」仍要求**最高 AI 难度**、真人在整场最终结算时存活，**不要求最终排名第一**。

### 3.5 旧存档与角色权限迁移

- 不做“历史玩家保留全部角色”规则，**所有人在 0.5 初始适用相同的新解锁规则**。
- 旧对局历史、旧累计档案数据和旧成绩应正常保留；不用于补发 0.5 成就，也不因为角色重新锁定而清空其他资料。
- 角色可用状态与成就完成状态分开持久化：成就解锁可开放角色；一键解锁全部角色可直接开放全部角色，**不反向修改成就**。一旦玩家在 0.5 中已经合法开放角色，后续加载不能再次套用迁移默认值将其锁回去。
- 如 0.4 进行中存档保存了正在使用的角色，不应仅因 0.5 大厅角色锁定状态而直接删除、破坏或强制重写对局；如当前存档结构无法兼容，工程 AI 应先报告冲突并提交最小兼容方案，不能擅自丢档。
- 不能使用“是否空档案”这种猜测作为迁移条件。工程 AI 应根据已有版本标记和存档结构制定**可幂等**的迁移方式；必要的协议变更先说明。

## 四、验收检查清单（代表性用例）

- [ ] 连续失败 4 次后，在同房双竞拍出现“一成一败”：A03 **不达成**，且连续数归零，和 A/B 结算顺序无关。
- [ ] 连续失败 3 次后，同房双竞拍两笔均失败：连续数达 5，A03 **达成**。
- [ ] 连续失败过程中观望／扰乱，随后继续竞拍失败：既有连续数保留；另起一局则重新计数。
- [ ] 正常竞拍失败但屏障退款：A01/A02 失败累计正常增加，C02 可以依据真实退款事件授予。
- [ ] 一组奖励同时有最高价与合作区资格，最终实际发放一件道具：对应资格成就可同时计入，但不复制发奖。
- [ ] 最高价资格奖励经尾巴复制为两件：B02 只增加 1 次；若宝箱问号奖励实际交付两件，E05 增加 2 件。
- [ ] 合作区排名不足但原本就有最高价资格，幸运脚触发相关流程：D05 不应错误授予；只有幸运脚新增必要资格时才授予。
- [ ] 开局自带「硫磺火」或「更多选择」：不完成 E04/E02；后续房间真实获得才完成。
- [ ] 六面骰翻倍后积分被其他效果清零：C06 仍达成；穷人护符实际加分后被清零：D04 仍达成。
- [ ] 永恒六面骰作用于原本 0 分的房间：E01 不达成；作用于正分并清零：E01 达成。
- [ ] 同房两个清零效果均真实触发：C07 可以达成；不依赖最终零分推断触发原因。
- [ ] 生存层末多人并列存活者最低层成绩：相关真人都可满足 F03，不额外运行随机判定。
- [ ] 房间结算已达成成就后立即放弃整局：已达成成就不撤销；尚未完成结算的事件不记账。
- [ ] 读取旧回放、重复导入、恢复后重放同一结算：成就及计数不能重复入账。
- [ ] 0.4 存档在 0.5 继续：只计升级后新发生的结算事件，旧历史不回溯。
- [ ] 升级 0.5 后，新老档案默认均仅以撒可选；一键解锁开放全部角色但成就仍保持原进度；再次启动不会重复锁定已经开放的角色。

## 五、实施边界与剩余非本轮决策

本轮 **12 项边界已经裁定**，工程 AI 可以据此开展最小实现设计、测试和相关字段核对；不再将这些规则作为未决问题重复询问。

**仍未指定的事项**包括：成就是否隐藏、分类页面入口、提示动画和进度展示形式等 UI 细节；这些事项在配套设计表中仍属单独待讨论范围，不代表授权自行扩展大型任务系统。

实施前应先核对现行代码能否提供上述权威事件及真实原因。如缺少数据，请说明**具体缺口、最小需要补的字段与可验证的替代方案**，不要改动核心结算规则，更不要因规则实现困难而暗改成就条件。

## 六、工程核对后的补充裁定（R13～R19）

日期：2026-10-14。工程AI核对现行代码后提出六项补充边界及模式累计范围，用户确认按建议补全方案，暂不修改代码。以下是已确认规则，不作为待实施时重新询问的产品问题。

### R13．竞拍失败采用市场资格判定阶段

A01～A03采用与屏障退款相同的失败口径：有效正常竞拍在**市场获奖资格判定完成、更多选择与尾巴后处理之前**没有取得对应组资格。屏障退款不改变失败事实；取得资格后被更多选择随机舍弃或被尾巴消除，不算正常竞拍失败。

同房双成功、随后随机舍弃一组，在A03中仍属于有成功的房间，连续数归零。现行返回的entitlements已经经过更多选择删除，不能仅凭终态列表判断失败。不得因此重排结算步骤；通过现有占位与原因事件解释资格阶段。

### R14．D06采用全额名义报价

D06成立条件为：有效正常竞拍的**名义报价等于行动前当前可用资金，且资金大于0**。行动前资金已包含本房进场经济效果；不是公共层资金或角色初始资金。

Steam大促减少实际扣款、屏障或福袋后续退款，均不撤销已发生的全额报价。资金100、报价100、实际扣款70可以成立；不要求结算后余额为0。双竞拍仍保留现行报价总和不超过当前资金50%的限制。

### R15．旧事件不作为连续／复合条件的上下文

升级前的事实不累计，也不作为0.5连续或复合条件的历史组成部分：

- 旧局升级时A03连续数、C07组合状态从空状态开始。旧4败＋新1败不达成A03；旧永恒六面骰清零＋新巴比伦清零不达成C07。
- F04要求正式第1～3层通过事件均属于允许统计的新事件。旧前两层＋新第三层不达成；不能把升级后的第3～5层改称“前三层”。
- F05要求真人淘汰事件发生在升级后，并由正式终局确认其属于最后一次淘汰。升级前已淘汰、升级后仅由AI确认终局，不授予F05。
- F02依赖新产生的正式终局：旧进行中局正常续玩，在0.5产生正式终局且真人最高难度存活，可以成立。读取升级前已经完成的终局不成立。

已经在0.5合法处理的活动局刷新／续玩不再次初始化这些状态。导入旧检查点也不能生成新身份来重复记账；迁移基线和事实去重共同约束。

### R16．进房资金结算独立入账

偷钱袋和利息发生在进入房间时。进房经济结算是独立的有效结算单元：该结算完成、成长档案成功保存后即可入账，**不等待本房竞拍结算**。此后未报价便放弃，不撤销D01／D03已合法入账的进度。

升级前已经发生的进房事件不计入，即使本房竞拍在升级后完成。恢复时对历史命令重新执行preparePlayersForRoom只是重建，不是新进房事件；不得在读取、预览、恢复、教学或只读回放路径挂接发奖。

分别记录进房、房间、层末、终局处理边界。保存失败仍是待处理，不显示已获得；不为了记录成就额外执行进房经济效果。

### R17．E01按正式精度的未清零应得分判定

E01要求永恒六面骰真实clear_score触发，且**依现行scoreStorageDecimals=4得到的未清零应得房间积分大于0**。未舍入浮点值为正、但正式四位积分为0，不成立。

未清零应得分是评分阶段同一输入、同一已发生倍率的应得分，尚未应用清零及之后新获心脏的追溯效果；不重新掷骰，不改变原评分或清零顺序。C07不套用这个限制。

当前评分事实没有直接保存该数值，舍入后分项再乘倍率不能保证精确还原。实施时评估补最小诊断事实scoreBeforeClear及其严格校验／编码／恢复；该字段是候选技术名称，不代表本轮已修改格式。不得从待审新实现覆盖历史golden来掩盖事实或随机流变化。

### R18．主动档案替换允许回到备份状态

保持现行明确替换、不自动合并语义。玩家主动恢复更早0.5档案或0.4档案，可以回到备份中的成就、进度与角色状态；“永久入账／不撤销”针对放弃对局和正常加载，不表示明确替换备份永不回退。

- 恢复已有0.5成长模块时保留该快照，不再次执行默认迁移、重新判定或重复弹出达成。
- 明确恢复0.4档案时保留其旧成绩／历史，按新体系初始化默认仅以撒，不补旧成就。这是主动替换后的旧档案初始化，不是普通加载时重新锁定。
- 不自动保留或合并被明确替换掉的本机成长。恢复前预览须说明快照可能早于当前进度。
- 成长凭据也随档案快照替换，不承诺独立于全部档案回退的永久外部领取总账。恢复本身不入账；续玩仍依检查点边界、来源与当前凭据只处理合格的新事实，不将旧事件重建当成新结算。

正常启动绝不清空合法0.5状态；损坏／未知模块保留原资料并报告，不能冒充0.4空档案重新初始化。

### R19．A～E共享正式模式累计

A～E在经典与生存两种正式模式共享成就状态和跨局累计，不额外增加模式或难度门槛；A03／C07等单局条件不能跨局或跨模式拼接。F只统计正式生存，F02保留最高难度条件，其余F项不新增难度限制。

仅真人入账，独立教学不计。AI环境事件可用于B04等公开结算条件，但不记录AI个人成就。隐藏奖励只在实际发生／发放后判定，不能访问未来秘密奖励来提示成长。
