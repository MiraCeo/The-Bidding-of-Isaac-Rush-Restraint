## 一、原专项版本与持久化边界

- 档案正文1、独立档案文件1、压缩容器1、对局v5及growth1保持。固定模块名仍是`achievementRegistryV1`，**内部schema支持1和2**，不能把模块名尾缀当成schema版本。
- schema1保留原严格校验：最多2048条、896KiB模块；非法或未知版本不转空、不自动修复。新逻辑视图仍为逐条完整receipt，不要求调用者了解紧凑传输。
- schema2最多16384条；896KiB模块、1MiB整档及8192完成登记上限不增加。条数上限不是保证所有构成能放满：根数量、时间、指标、历史、完成登记及未知扩展共同占空间。
- 小账本保持schema1。正常协调写入新增事实，或确实新增手动授权后，候选达到256条即无损转schema2；已有schema2不降级。单纯读取、预览、重复事实或重复授权均不触发迁移写入。
- 提供纯函数`compactAchievementProfile`供维护／自动化使用：仅接受合法旧账本，保留整档createdAt／updatedAt、手动授权时间、所有事实与达成时间；无UI按钮、无独立写入后门。实际持久化仍须既有同源协调、原文守卫与事务。
- **早期0.5程序不能读取schema2**：保留原模块名使旧严格读取器明确拒绝未知版本，而不是忽略新模块并当作空档重新授予。携带此模块的独立档案／配套完整备份同样需要新读取器；外层版本未变不代表内部向旧程序兼容。旧带版本HTML保留但不回写数据格式。

## 二、无损编码

schema2包含且仅包含：

```text
version: 2
catalogVersion: 1
activatedAt: 原ISO时间
manualUnlockAllAt: 原ISO时间或null
count: 凭据数
roots: 按首次出现排序的[模式0经典/1生存, 完整32字节root的Base64][]
data: 标准Base64正文，分成最多8192字符的块
```

每条正文按原全局顺序编码：

1. root字典索引，无符号最短varint。
2. 父节点的1基全局索引，0表示null；只能引用此前节点。
3. 阶段字节（entry=0／room=1／floor=2／final=3）与position字节，分别保留，不能把终局和下一层入口的排序碰撞当同一事件。
4. 相对上一条at的毫秒差，第一条相对activatedAt；有符号zigzag转无符号最短varint，允许时钟回退，原毫秒时间精确保留。
5. 完整32字节authorityHash，不缩短、不用指标摘要替代。
6. 原原因指标：entry两个varint；room前四个varint、score是否存在的0/1标记及存在时乘10000的安全整数；floor一个varint；final前两个varint及淘汰层null=0／层号+1。

receipt key按原SHA256公式从完整mode／root／parent key／authorityHash／stage／position重建，值与旧账本逐项相同。不以聚合累计替代领取凭据，不删已结束对局，不合并同root的独立分支，不删首次达成依据。

读取先核对外壳、日期和模块字节，再限制条数、字典、块长和正文总量，解码后仍执行同一套事实／父前缀／顺序／去重／原因与累计安全整数校验。拒绝非规范Base64、非最短／溢出varint、未来父节点、未使用或重复根、未知阶段、尾随或截断字节；不存在“二进制合法就可信”的快捷路径。SHA256身份用于确定性事实标识，不把本机档案宣称为服务器认证证明。

## 三、核验优化

- `applyGrowthContext`一次建立已验证索引，逐单元检查已确认／忽略前缀并增量处理新事实，最后只安装一个候选；不再为最多78个单元反复全量扫描。
- 配套档案前缀核验复用同样的权威单元索引，不在每次查找时重新读账本。
- 当前同步协调事务内最多复用4份**完整规范化账本正文完全相同**的验证快照。未知扩展等档案其余部分仍逐次校验；缓存不替代整档预算、来源或代次守卫。
- 快照私有隔离，投影／索引查找／解码视图不能反向污染它；原始schema1接口保留原对象语义但缓存不保存调用者可变引用。正文变化立即重验，非JSON／稀疏数组不得利用规范化碰撞命中缓存；超出4份则淘汰缓存而非淘汰持久化凭据；同步调用结束／异常即释放，不跨请求或跨页共用。
- 批次中任何失败使候选不可提交。模式检查点、档案、完成登记、游标与提示仍按既有事务提交；失败最多留下pending检查点，不提前确认成长。明确档案替换／旧排队任务保护保持。
