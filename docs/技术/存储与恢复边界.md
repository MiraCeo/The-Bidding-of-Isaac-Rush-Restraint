# 存储与恢复边界

当前0.5.6，原存储键／恢复入口保持，v5支持具名growth1可选续玩扩展。正式四阶段已接协调自动记账及重试，当前UI完成／档案替换／配套恢复共用同源Web Locks；缺能力不授予成长。新增本机档案替换代次键只用于区分明确回退，不是独立领取总账。本文说明当前职责，具体字段见现行协议补充。

0.5.6在原growth1新增milestonesFrom，内部账本支持schema4／catalog3首次确认位置／时间和新原因；旧1／2／3保持严格读取。可靠旧金额／机会／complete可继承，新等级需新正式事件成功保存确认，单局复合不借旧前缀；完成按原root去重。无新增存储键或第二套领取账本，见[0.5.6记录](../记录/0.5.6累计阶梯与成就扩充.md)。

## 数据各归其位

| 数据 | 作用 | 边界 |
| --- | --- | --- |
| 经典／生存自动检查点 | 各一份续玩位置和草稿 | 两模式分开；不是多存档槽，自动存储未压缩 |
| 最近完成回放 | 各模式最近完成局的原事实 | 不是长期全量库，归档失败与检查点失败分别处理 |
| 轻量完成历史 | 档案中最近最多200条结果 | 不承诺都有完整回放，不代表终身总数 |
| 完成累计与去重凭据 | 登记启用后的基础统计 | 重复恢复／只读查看不增；旧丢失历史不猜回填 |
| 玩家档案 | 完成记录、累计／凭据与已保留扩展数据 | 两模式共享，与显示偏好和完整库分开 |
| 0.5后台成长账本 | achievementRegistryV1紧凑结算凭据、手动角色授权及可推导进度 | 正式真人结算成功提交才写入；旧schema1最多2048、新紧凑schema2／3／4最多16384凭据；896KiB模块及整档1MiB保持，各自有界，旧数据读取不自动发奖 |
| 完整回放库 | IndexedDB原正文、索引、首次来源与删除证据 | 默认100局／64 MiB应用上限，满库停止新增、不自动淘汰 |
| 显示偏好 | 精度、默认面板与动效 | 恢复默认不重置任何游戏数据 |

存储受浏览器／来源限制，换协议、地址、浏览器或文件路径不承诺共用资料；移动程序或切换环境前另行导出需要的数据。诊断的文本大小不是物理磁盘或通用剩余配额。

## 五类可携带文件

| 文件 | 包含 | 确认后的行为 |
| --- | --- | --- |
| 续玩v5 | 一局检查点、命令／事实与草稿 | 严格核验后载入；不默认替换档案 |
| 回放v5 | 一局已发生事实，可为进行中片段 | 只读；不变成当前局、不运行AI、不重复登记 |
| 本局完整备份v5 | 一局检查点、配套回放、本机档案快照 | 默认只载入局；替换档案需明确勾选，来源变化需重新核对 |
| 独立档案文件v1 | 完成历史、累计／凭据、已保留扩展数据 | 明确替换档案，首版不自动合并；不包含两模式续玩、完整库或设置 |
| 整库备份v1 | 两模式全部原正文、索引、首次来源、旧／新删除证据 | 核对新增／重复／删除保护后原子增量追加；不包含续玩、档案或设置 |

对局读取仅当前v5，旧v2／v3／v4拒绝，不自动迁移或删除旧资料。压缩容器仍v1，当前原JSON与压缩.json自动识别；用途按内部mode／kind判定，不按文件名猜。档案正文1、独立文件1、容器1、库schema1、整库1是不同版本维度。

单份对局8 MiB与整库文件160 MiB、正文64 MiB／100份、元数据16 MiB／8192标记分开有界，不把整库限额放宽到普通对局。

## 数据保护

- 读取先预览，确认才安装。取消／换文件／离开后丢弃迟到结果，旧候选主动释放，不请求迟到下载。
- 本局完整备份默认不替换档案；勾选后档案原文变化会阻止旧预览替换，重新核对需重新勾选。
- 配套检查点／事实／草稿／档案先写成功再切换内存；失败回滚不覆盖其他页面新写的数据。当前UI档案写入参与同源Web Locks；不保护同时打开的旧程序／未知写入者，不是崩溃日志。
- 整库恢复核对三个store未变后单次原子追加。本机首份正文／来源不覆盖，本机已删除记录不自动复活，备份内标记不删除本机存活记录。
- 经典等价去重仅限定权威事实与可核验的说明邻居，保留旧物理键／首次正文与来源；已有副本只读标注、不自动删。旧无说明删除标记仅按原键保护。
- 生存淘汰后积分／参与记录冻结，不用新默认AI或新参数重建旧局。内部AI身份与文件头版本不是同一件事。
- 已存在的成长模块严格校验，坏／未知模块保留原文不重置；没有模块的旧档案只读不自动初始化。当前UI完成／档案替换／配套恢复均接同源协调；不保护旧程序或未知写入者，不宣称崩溃事务。
- 全库核验显示真实阶段，取消在边界响应；单次同步JSON片段不保证即时取消，不以提速名义跳过核验。

## 0.5第三批B处理边界

自动本机重载保留pending重试；显式文件导入忽略先前日志，不据此补奖，但已在配套档案入账的同局前缀可正常继续。明确档案替换生成新的本机代次；旧上下文未入账或已被快照移除的前缀不会重新授予，新产生的事实可继续登记。成长游标只在检查点／档案事务成功后确认；失败最多保留pending检查点，原档案不改，重试只处理一次。

模式检查点原文由本次客户端持有，另一页面改写时不自动rebase、覆盖或静默恢复。配套恢复捕获实际提交原文；等待任务取消与迟到确认不能恢复旧局。详见[第三批B](../记录/0.5.0自动入账与写入协调第三批B.md)。

## 长期成长账本补充

模块命名空间`achievementRegistryV1`固定，内部schema1／2／3／4独立演进。0.5.3新事实使用schema3／catalogVersion2，旧凭据key与时间不变，不对旧档案追溯新六项；growth.expansionFrom只允许继续游玩的新权威阶段贡献新增事实。导入忽略前缀、档案代次与失败回滚同样覆盖新增complete阶段，见[0.5.3记录](../记录/0.5.3新增成就与收藏札记.md)。下面保留原schema2迁移规则。新增写入达到256条无损转紧凑schema2，所有原key、完整摘要、父分支、指标与时间保持；只读／重复不迁移、不补奖。早期0.5读取器将明确拒绝schema2，不是向旧程序兼容。条数上限不保证共享1MiB能同时放满，达到任一预算仍保留旧档并pending，不清旧凭据。字段与有界核验复用见[技术说明](./0.5成长账本紧凑存储与核验复用.md)。
