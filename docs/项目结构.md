# 项目结构

更新日期：2026-10-16；适用于当前0.5.9本地交付。本文描述文件职责，不记录逐次版本测试结果。

当前成就由`revision058-catalog.ts`在0.5.7基线上定义107枚／25系列；`revision058-facts.ts`只读本人轮空组数／屏障正退款行动数／幸运脚必要交付组数，`revision058-evaluation.ts`处理C～F阶梯、同局两房与前置层数。原`revision057-facts.ts`只读权威按组／轮空／房间道具与终局排名，`revision057-evaluation.ts`处理新累计。`v056-*`冻结旧目录／分级／系列供历史语义，不是重复注册；`registry.ts`推导旧纪念和保留权限。完整新协议见[0.5.8记录](./记录/0.5.8CF成就阶梯与挑战调整.md)，旧数据清理及全局重编号仍为TODO。

0.5.9分类显示由`series.ts`只读汇总匹配子级的卡片，`achievement-progress.tsx`先统计全分类可选数量再显示当前分类；顶部徽章总览与账本保持。见[显示修正记录](./记录/0.5.9成就卡片分类与筛选计数.md)。

## 二、程序与代码导航

| 位置（相对仓库根） | 职责 |
| --- | --- |
| `web/main.tsx`、`web/index.html` | React入口与网页入口 |
| `web/components/game/game-app.tsx` | 两模式控制器、进度入口、导入／回放来源分发 |
| `web/components/game/classic-game-app.tsx`、`survival-game-app.tsx` | 各模式真实阶段、草稿、推进与保存状态 |
| `web/lib/game/` | 游戏规则、随机流、角色／道具、市场结算、AI与模拟 |

| `web/lib/game/survival-session.ts`、`survival-results.ts`、`survival-content.ts` | 正式生存状态机、淘汰／全员排行、无黑冠内容 |
| `web/lib/game/survival-ai.ts`、`survival-difficulty.ts` | 生存AI策略、难度及最高基线保护 |
| `web/lib/ui/game-session.ts`、`survival-client.ts` | 权威游戏状态与界面草稿适配 |
| `web/lib/ui/mode-session.ts` | 内部模式边界／原型辅助；不当作正式UI主控制器 |

| `web/lib/ui/game-save.ts`、`game-replay.ts`、`survival-persistence.ts` | 模式各自检查点、事实回放、核验与保存 |
| `web/lib/ui/compressed-file.ts` | 有界无损压缩容器 |
| `web/lib/ui/replay-library.ts`、`replay-library-backup-format.ts` | IndexedDB完整库、去重／删除证据与整库备份 |

| `web/lib/ui/achievements/` | 0.5规则、账本与保存接口；第三批A／B四阶段捕获／自动入账、growth1续玩上下文与配套游标、失败重试；当前UI档案写入共用profile-write-coordinator及profile-operations；P1-1角色权限与P1-2基础成就展示已接入 |
| `web/lib/shared/` | 共用JSON事实和SHA256；不持有游戏会话 |
| `web/components/game/`、`web/components/ui/` | 游戏视图与通用UI组件 |
| `web/components/game/game-header.tsx`、`utility-page-heading.tsx` | 共用品牌／导航／小版本、独立上下文行与标题／说明／返回区；桌面外壳宽度在globals.css集中定义 |
| `web/app/globals.css` | 主题、布局和响应式样式 |
| `web/assets/items/`、`web/public/` | 道具素材、清单、favicon及分享图片 |
| `web/lib/**/*.test.ts`、`web/scripts/**/*.test.mjs` | 规则／客户端／文件／构建与报告型测试 |

数据分层与文件用途见[存储与恢复边界](./技术/存储与恢复边界.md)。不要把早期文档中的“生存未接入”“v3/v4当前格式”当成现行结构。

## 三、本机生成目录

以下目录按原配置忽略，不移动或清空已有数据：

- `web/node_modules/`：安装的依赖。
- `web/dist/`：普通网页生产构建。
- `web/dist-offline/`：固定HTML、带版本HTML、manifest与SHA256清单。
- `web/releases/`：release交付目录。
- `web/work/`：研究样本、恢复数据、计时／日志／截图及临时证据。
- `.next`／`.vinext`／`.wrangler`等现有开发缓存：本轮不改框架或清理缓存。

原来散在`web/`顶层的`simulation-output*.txt`已原字节迁至`web/work/历史控制台/`，未删除控制台历史。归档机器可读研究JSON继续随源码管理，见[早期研究数据](./归档/早期研究/研究数据/README.md)。

## 四、维护约定

1. 概览写README，版本变化写[项目更新](./项目更新.md)，未完成任务写[TODO](./规划/TODO.md)，完整证据写记录／归档。
2. 当前规范不因文件名v1自动归档；已替代协议、已结束实验和阶段快照进入归档。归档不等于数据无用或自动改变正式参数。
3. 移动文档同步修正相对链接；历史正文／种子／计时／构建来源保留。代码路径按仓库根表达，文档链接按所在文件表达。
4. 不随目录整理修改规则、AI、文件协议、版本号或旧HTML／manifest；不删除旧资料、不自动commit／push。
