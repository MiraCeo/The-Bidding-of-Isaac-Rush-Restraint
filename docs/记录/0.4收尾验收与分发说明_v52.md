# 0.4收尾验收与分发说明 v52

日期：2026-10-14；本批开发预览0.4.11。前批0.4.9／0.4.10已提交`533fac1`，未push。本文件为现行入口与收尾清单；此前各阶段测试、协议、HTML来源和限制仍按原记录保留。

## 一、当前交付范围

0.4是整理与优化版本。已具备经典／生存、四档生存AI与教学、压缩文件、进度中心、长期完整回放库、独立档案、基础完成登记／统计、经典恢复／等价去重、完整备份保护、整库批量备份／增量恢复、大库首轮测量、长操作阶段／取消／资源释放及进度布局统一。

成就与角色解锁未实施，留0.5。移动端、云同步、任意赛制、自动清库／批量删除、自动播放／历史分支和紧凑差分编码不作为0.4结束条件。现有角色、AI、计分、正式斩杀线与权威事实不因整理改变。

## 二、现行入口与保存职责

主导航统一为**游戏／排行／进度／设置／规则**。品牌稳定，页面名在内容标题显示；回放文件可使用表达只读用途的专用标题。

| 入口 | 内容／操作 | 不包含或不改变 |
| --- | --- | --- |
| 游戏 | 当前真实阶段、选角、报价、结算、推进、明确重新选角 | 浏览其他页面不提交行动 |
| 排行 | 经典公开积分／资金、结算积分／争夺；生存另有实时／终局生存榜 | 不公开本房秘密报价或预测淘汰 |
| 进度 → 总览 | 两模式当前局、继续／查看终局及实际自动保存状态 | 不模拟多存档槽 |
| 进度 → 对局记录 | 本局／最近回放、最多200条轻量记录、长期完整回放库及整库备份／恢复 | 轻量记录不是完整回放或终身累计 |

## 五、分发方式与已知限制

1. 每次程序变更执行类型／lint／回归、网页与离线构建；普通`build:offline`的manifest验证字段为空时不称release门禁通过。
2. 分发用`web/dist-offline`中的带版本单个HTML；固定`以撒的竞合.html`供原地址验收，不发送网页`dist/index.html`作为离线包。对局／档案／整库文件另行保管，不嵌入程序。
3. 更新后重新加载核对游戏版本、构建标识和规则兼容。旧包／旧manifest不回写来源，不把源码commit当作已上线。
4. 自动续玩、最近回放、档案、偏好与IndexedDB完整库各自存储；换浏览器、协议、来源或文件路径不承诺共享资料。移动程序前先导出所需文件，不以HTTP研究数据代替离线资料。
5. 完整库默认100局／64 MiB为应用上限，不是浏览器剩余空间；单份对局8 MiB与整库文件160 MiB、元数据16 MiB／8192标记分开。满库停止新增，不自动清旧记录。
6. 全库导出／未命中完整核验仍可能约10秒；已补阶段／边界取消和临时资源释放，单次同步JSON片段不保证即时取消。是否进一步调度或Worker按实测决定，不作为结束版本的必做架构重写。
7. 直接file完整流程、真实下载往返、非Chromium／低内存、IDB物理配额、最坏600说明构筑和极端多页交错未全覆盖。按实际分发范围补验，确认数据故障优先，不无限延长版本。云部署、容器运行与移动端另列。
