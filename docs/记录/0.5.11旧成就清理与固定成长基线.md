# 0.5.11 旧成就清理与固定成长基线

日期：2026-10-16。用户先将“完全清除旧版本成就数据”列为TODO，明确不移除成就继承功能，现已授权开始清理。本批实现运行程序的自动清理及恢复隔离，**不通过开发工具访问或删除用户真实浏览器存储，不进行未授权实机验收**；用户打开新版时按下述规则执行。全局编号整理仍单独后置。

## 一、固定边界，不按每次升级清零

- 新增固定元数据`progression.modules.achievementBaselineV1:{version:1}`，表示已经处于清理后的成就数据基线。新建档案即携带，未来普通版本升级保持1，不随0.5.12等补丁号变化。
- **0.5.10及以前的真实旧档案没有此标记。**先严格核验完整旧档案和成长账本，再构造清理候选；不按创建时间、导出日期、文件名或`exportedBuild`猜测。带当前标记的档案即使导出标签很旧，也正常继承，不再次清零。
- 未标记旧成果读取时不再作为当前成就／权限展示，但读取不写存储，并明确提示“清理尚待成功保存”。实际清理需同源协调成功提交；失败保留原文，提供重试，不把投影排除当成已经物理保存。
- 未知基线、损坏旧模块或无法核验的资料拒绝，原数据保留。不能为了清理绕过校验或把未知资料当空档。

## 二、清除与保留的精确范围

| 数据 | 本批处理 |
| --- | --- |
| 未标记旧`achievementRegistryV1`中的凭据、累计、达成时间、分期激活位置、旧纪念 | 原账本事实全部清除，不能靠保留旧凭据再次投影出旧成果；有原模块时以新空模块替换 |
| 未标记旧`progression.achievements`预留记录 | 清空成就记录映射，不拿这些旧值补新账本 |
| 旧成就派生的角色权限 | 清除；游魂等按当前前置重新取得，默认以撒开放 |
| 真实手动一键授权 | 保留权威账本的`manualUnlockAllAt`及原时间，仍不生成就；手动授权四名非默认角色继续可用 |
| 预留角色字段中明确成就条件ID | 去掉`E01+A02`、`legacy:E01+A02`等成就派生条目；不扩大到手动或未知非成就来源字段，预留字段仍不直接授予正式权限 |
| 完成统计、历史与`completionRegistryV1` | 原内容完整保留，不重置成绩或重复完成登记 |
| 对局、草稿、回放／回放库、偏好、其他扩展模块 | 不删除，不修改玩法事实；更新检查点时只处理其成长元数据，原命令／正式结果与回放来源保留 |
| 旧外部备份、旧HTML及Git历史 | 不改写／删除；本版本读取旧资料先核验，再对清理候选执行明确恢复，不把历史文件原地抹掉 |

`updatedAt`反映清理写入时间，`createdAt`、对局历史时间及手动授权原时间保留。本批107枚条件／ID、57卡、25系列、分级、隐藏与角色实质前置不变，不进行全局重编号。

## 三、旧续玩与恢复不回灌

成长上下文新增可选`growth.baseline:1`，仍为growth1／外层v5，不变更账本schema1～6或另建领取总账：

1. **旧检查点先按原格式及命令独立核验。**缺标记的旧上下文不会被当成新领奖事实；旧完整备份的未清理档案与旧已确认前缀在清理前仍须匹配，损坏配套关系拒绝。
2. 本版本保存／导出／继续旧局时，移除其旧成长`units`、确认游标和旧忽略前缀；以实际权威阶段建立`excludedThrough`，四个已有分期边界不早于该点，并标记基线1。不是删除游戏命令或回放，也不按旧history补成就。
3. 第一条新现场阶段从该排除边界之后开始，单局连续／复合从新前缀跟踪，不能把清理前的失败／退款／转化与清理后的事件拼接。重复恢复旧资料不会补回旧成就；正式终局已发生的旧结果不因加载再授予完成章。
4. 清理后的档案与仍在等待保存的旧上下文共存时，旧前缀明确排除；新的基线1上下文仍严格核对已确认凭据，缺少配套凭据依然拒绝，不为了兼容旧数据取消当前保护。
5. 客户端只在内存对局仍等于排队快照时接受旧→新空前缀的确认结果；若已继续游玩，不用迟到结果覆盖更新的上下文。缓存键含完整成长上下文，新基线不会复用旧成长正文。

新独立档案导出／预览／恢复、经典与生存完整备份的当前写入候选都清理旧成果；原文件先校验，解析不写用户存储。明确替换当前基线的档案仍按既有快照回退语义，不自动合并；这与“普通升级正常继承”不同。
