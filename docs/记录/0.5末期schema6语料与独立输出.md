## 一、现行语料，不改名复用旧报告

- [语料工厂](../../web/lib/ui/achievements/closeout-corpus.test-helper.ts)从现行状态机和成长生命周期捕获：经典seed42、以撒正常报价；生存seed3、以撒／最高难度的观望与按层节奏报价，以及简单难度的节奏报价，共四条确定性模板。无人工改道具、淘汰线或AI规则。
- 全部使用固定基线1，四个前瞻边界从新局开始；经`applyGrowthContext`实际进入schema6／catalogVersion5，校验entry／room／floor／final／complete的5／17／4／6／5字段长度。淘汰后真人事实依现行流程冻结，等待正式终局产生final／complete，不把AI后续房间算给真人。
- 规模工厂提供经典、生存、混合／分支三种构成，支持0～16384条成长凭据及历史0～200、其他扩展填充、完成凭据0～8192的组合。完整key／root／authority仍为256位摘要，保留父链接、原因指标、激活位置和独立时间。
- 放大时**只复制现行真实事件模板中的指标**，root／authority身份及分支拓扑是合成的，不能当真人实玩对局、完整回放证明或可导入玩家档案。分支共用根的多个complete不重复增加正式完成进度。
- 现有三条生存模板均为第一层淘汰、等待正式终局的13单元路径；简单／最高难度的final标志不同，经典为31单元。它们覆盖冻结真人事实，但**不能代表真人多层存活或最坏生存容量**，该路径扩充明确留后续测量任务。
- 零凭据样本是携带基线1、未激活成长账本的空档案，不伪造`cf.from=0`或声称不存在的空wire是schema6。
- 完成凭据压力采用1个合成计数种子＋其余明确标记的已观测／未补算键，不把8192个键称作8192局真实完成；与历史200条及扩展占用分别记录。

## 二、独立运行与输出

在`web`目录运行：

```powershell
npm run report:ledger:corpus
```

该跨平台入口通过当前Node启动单worker Vitest，不启动服务器或浏览器。每次分配新的`web/work/v05-closeout-ledger/corpus-随机串/`，不维护会覆盖旧数据的固定报告文件。默认普通测试跳过该报告；缺少合法新运行目录时，直接手工设置报告开关也会失败。

| 文件 | 内容 |
| --- | --- |
| `run.json` | 唯一运行标记和分配时间 |
| `corpus.json` | 四条生命周期模板、完整上下文、每种构成64条的合成档案样本；带非玩家备份类型标记 |
| `manifest.json` | 0／64／256三种规模×三种构成的9行有效性／体积样本、模板摘要、源码指纹、实际运行环境及目录／基线信息 |
| `status.json` | 子进程完成或失败状态；失败资料保留，下次分配新目录 |

[输出器](../../web/scripts/ledger-corpus-output.mjs)核对工作区、新目录及运行标记，写入使用排他创建；拒绝旧`v050-ledger`目录、路径穿越、未分配目录及重复文件，不覆盖失败样本或既有报告。来源包含实际Git提交、dirty状态、功能／测试／构建输入的SHA-256和运行时，不拿应用版本号代替源码身份。

**这只是语料生成、语义往返和体积样本，不是完整容量／性能测量。**0／64／256样本通过不能推出16384条普遍可保存，这些固定策略也不代表107枚成就原因均已覆盖。更大规模、时延、内存、硬边界和真实存储行为继续留在[收尾TODO](../规划/0.5后续开发TODO.md)。
