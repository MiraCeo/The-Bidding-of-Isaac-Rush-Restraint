日期：2026-10-15。承接第三批A的 `f79508c`；本批为P0-3数据链路收口，不新增成就条件、赛制或AI规则。用户允许适时commit；push仍须明确命令。本批不push、不覆盖历史离线包，不开启角色选择限制或新增成就展示页。

## 一、正式四阶段自动记账

[client-persistence.ts](../../web/lib/ui/achievements/client-persistence.ts)与[客户端hook](../../web/components/game/use-live-persistence.ts)连接实际经典／生存控制器：进房资金、房间结果、真人层末、正式终局捕获后进入协调保存。成长与终局统计使用同一当前档案候选；同步回滚事务将检查点处理游标、成长档案及必要的配套回放一起提交。

- 不等整局结束才发成长；新进房已经成功提交的资金进度即使未报价便重新选角也保留。放弃不撤销已入账成果，未成功保存的pending不冒充永久入账。
- 同一权威单元重复提交／自动刷新／重复确认不会重复增加进度或更新时间；只读回放、教学和AI个人事件不增加。
- E01仍采用A批捕获的四位真实评分旁路；原因和市场资格仍使用已裁定口径，不重跑奖励或改变正式随机数。
- 经典保留带成长的已结束检查点；正常重载可以补完真实本机pending并去重，不依赖最近回放推断遗漏成就。生存终局使用已经缓存的实际回放快照，不增加UI-only快照重建。
- 成功后才合并处理游标；合并必须匹配root、排除边界、完整单元前缀及操作代次，迟到确认不能复活旧局或带入另一局元数据。

## 二、当前写入者共用同源协调

[profile-write-coordinator.ts](../../web/lib/ui/profile-write-coordinator.ts)统一锁名 `bidding-profile-write:bidding-player-profile-v1`。当前UI经典／生存自动保存与完成登记、独立档案替换、两模式配套恢复都经此协调；原同步helpers保留为底层事务／研究／测试primitive，不再有当前UI独立绕过同锁的档案写入路径。

每次持锁重新读取并严格校验档案；不使用预览或上一渲染的旧profile覆盖另一模式新增。当前模式的检查点原文由本客户端持续持有，只有自己的成功提交、明确新局／载入才更新基线。其他页面改写模式检查点后，正常保存及fallback均拒绝覆盖，重试也不会自动rebase。配套恢复将实际提交原文传给后续hook，避免下一渲染误把另一页的改写当成自己的来源。

Web Locks缺失时，原无成长统计／对局保存和明确档案恢复保持可用；成长只保留pending并提示重试，不把本页Promise队列当成同源锁。锁请求异常／取消仍报告真实结果。范围不包括同时打开的旧0.4／未知写入者，不宣称多键localStorage有浏览器崩溃原子性或跨来源事务。

## 三、文件载入和明确档案回退

growth1新增严格有界的可选操作字段 `profileEpoch` 与 `ignoredThrough`。前者为null或64位hex，后者为units长度以内整数；不参加match root或权威事实摘要，不是领取证明。单位事实仍通过已有隔离命令重建核验。

- 显式文件载入安装前将文件中已有units标为忽略；未在当前档案存在的单元不补发，即使文件携带pending或已确认游标。已在档案中合法入账的同局前缀可继续，后续真实新事件可统计。
- 正常本机自动重载不是文件导入：同一代次的真实pending仍可重试，单局连续／复合上下文照常延续。
- 明确独立／配套档案替换才轮换本机键 `bidding-profile-replacement-epoch-v1`；代次与档案同一回滚事务提交，失败不会只替换一半。内容完全一致的独立档案替换保持no-op。
- 恢复更早档案允许成就、进度及手动授权回退，不合并被替换成果。旧在内存／检查点／等待队列中的前缀在新代次忽略，不重授已被快照移除的奖励。控制器在下一真实行动前绑定新代次，所以新产生的事件仍可继续登记。代次变化通知还会主动保存操作游标，使未再行动的当前局也能立即与回退后的档案成对备份；不改变游戏对象或补奖。
- ignored前缀属于已处理但未必已授予；配套档案一致性只检查已确认且未忽略的单元。读取本身不激活或发奖；角色权限界面尚未接入，五角色仍可选。

## 四、保存失败、取消与提示

成长／统计／配套事务失败回滚已写键；允许成功保存单独pending检查点，不确认成长、不修改原档案、不显示已达成。状态说明检查点与成长／配套失败的区别，并提供最小“重试保存”。回滚不能完成时不再fallback掩盖，不自动清理资料；主检查点冲突时不覆盖另一页。

文件确认改为等待Promise结果；配套恢复成功才切换内存局。取消、换文件、重新核对、修改恢复选择或离开中断待锁任务，迟到结果不更新旧候选。取消已完成的同步提交不等于能撤销它；这不是崩溃日志。已成功入账的成果不会因正常重开被删除，存储失败下仍须按现有重新选角提示先导出需要保留的pending局，不声称放弃未保存日志也永不丢失。

经典按相同game／完整growth操作内容复用核心与回放序列化结果；草稿独立保存；写入事务跳过字节相同的键。生存保留实际回放snapshot缓存。只读诊断将本机替换代次归档案组，不展示其值、不清理数据。
