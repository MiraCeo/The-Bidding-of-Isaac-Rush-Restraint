# 0.5.0长期账本容量与核验优化

日期：2026-10-15。用户授权先做长期账本容量与核验优化，内容拓展继续待确认。仅本地开发、Node／DOM自动化、静态构建与离线目录自检；没有启动服务、浏览器或真实文件往返，没有push／部署／标签。

## 实施范围

- 新增无损schema2：根字典、父节点索引、完整256位摘要、时间差和精确原因指标；原receipt key及所有分支／首次达成时间保持。不丢旧凭据、不按root合并、不用聚合总数冒充去重证据。
- 旧schema1严格校验保留；新增写入达到256条自动紧凑化，重复／只读不写迁移。新schema2上限16384，896KiB模块／1MiB整档／8192完成凭据仍保持；早期0.5读取器明确拒绝schema2，外层协议版本不等于内部向后兼容。
- 同步协调事务内最多复用4份完整正文一致的私有验证快照；每次状态变化仍全验。整局上下文批量索引核对、增量处理并安装单一候选，代次／原文守卫、失败回滚和pending处理保持。
- 新增专项规格，覆盖确定性混合语料、旧时间与角色投影、JSON／gzip、恶意编码／上限、可变引用隔离、有界淘汰、批次失败、满旧账本失败重试及重复不再写。原规则与经典／生存黄金基线不放宽。

详细字段和迁移边界见[技术说明](../技术/0.5成长账本紧凑存储与核验复用.md)。本轮不改30项成就条件、角色前置、引擎、AI、正式曲线、道具或竞拍规则；[内容候选](../规划/游戏内容拓展候选.md)没有实施。
