# 0.5.9 成就卡片分类与筛选计数

日期：2026-10-16。按用户截图反馈修正“全部n／107”和六类固定徽章分母：分类导航应统计当前可浏览的卡片，并随筛选变化。本批仅调整只读显示，不新增成就或修改条件／等级／隐藏／角色前置，不执行旧数据清理或全局编号重排。

## 一、显示口径

- 顶部成就总览继续统计**107枚真实徽章**及各铜／银／金完成率，不随列表筛选改变，角色解锁数保持原逻辑。
- 下方“全部”和六个分类按钮改为**已获卡片数／当前筛选匹配卡片数**。不筛选时默认总数57，六类分别5／10／9／10／14／9，不再用107及13／24／15／22／18／15枚子徽章作分母。
- 三级系列只计一张。已获任一匹配子级即计为一张已获卡片，无论该系列已获1／3、2／3或3／3；卡片内原金属等级、已获级数与各级真实时间不变，不把部分达成标成全系列完成。
- **必须是匹配同一筛选的子级。**仅获铜时，“银＋已达成”不能借铜计数；搜索金级子ID也不能借已获银级增加分子。选择未达成时仍可显示部分达成系列中的未获级，但该匹配卡片的已获分子为0。
- 名称／编号搜索、达成状态及徽章等级共同改变所有分类的分子与分母。分类按钮是切换入口，当前选A不会让其他分类归零；“全部”仍显示相同搜索／状态／等级下全分类可选数量。
- 分组标题同步显示“已获卡片n／m”，与该组当前实际显示的卡片吻合。空分类不渲染分组，导航保留0／0；空结果可清除筛选恢复57张，原列数偏好不丢。
- 排序与排列不改变匹配集合或计数。隐藏成就仍按原列表策略搜索，未获真实名称不通过计数泄露；详情浏览不写揭示记录。
- 列表说明继续分别注明“显示x张卡片，涵盖y／107枚徽章”，两个单位不混用。

## 二、实现范围

[只读卡片汇总](../../web/lib/ui/achievements/series.ts)在现有卡片选择器输出上按`matchingIds`去重汇总；[成就页](../../web/components/game/achievement-progress.tsx)先按搜索／状态／等级选择全分类卡片，汇总导航数量，再取当前分类显示，避免分类与筛选互相错误归零。分组使用同一汇总器。

不改`data-achieved`全系列完成判断、`card.completed`、原成就投影、成长账本、持久化协调或数据恢复。外层v5／growth1、内部schema6／catalogVersion5、存储键、预算和核心游戏规则保持。当前107枚的实际条件仍见[成就总表修订5](../规划/成就总表.md)，0.5.8及更早交付数据不回写。
