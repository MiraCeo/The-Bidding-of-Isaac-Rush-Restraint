## 二、判定关键点

- 竞拍失败复用市场资格与原因证据：最高价／合作名额、幸运脚资格及more_options消除事件还原取得资格事实，不按最终道具数量或删除后的entitlements直接判断。
- A03整房处理：混合／双成功清零，双败+2，观望／扰乱保持。达到5后的候选状态不因后续成功而消失。
- B01／B02允许同组多来源实际交付；B02按机会计1，E05按实际copies计件。D05排除原先已有最高／合作资格。
- 扰乱轮空用group＋playerId＋slotType对照赎回；一个名额赎回而另一个仍空，可同时满足C01／C03。
- 六面骰／两种清零按triggers；尾巴消除／复制和更多选择按effectItemId；屏障与福袋退款明确区分。
- D01／D03只取真人进房money原因；D04按评分强化触发及当时持有数量，普通四件+5不冒充一件+20；D06按prepared资金与名义报价。
- 获得型只取awards，初始装备不计；BOSS房型与BOSS道具池区分，treasure原hidden奖励实际交付才计。
- 生存F03比较存活者权威survivalScore，包括并列；F04只认正式第0／1／2层全部合格通过；F05需要合格新淘汰和新正式终局确认，不能拿旧淘汰补奖；F02读局内显式highest，不把缺失难度猜成最高。

## 三、纯分析API的边界

evaluateAchievementRun接收**同一局**的有序唯一结算位置及调用方已经确定的eligible标记；baseline必须排除本局，只包含未来通过成长校验的0.5累计。调用两次相同输入返回相同候选，不修改输入。

该API不是领取／写入接口，也不是文件安全校验器。输出不能当作递增凭据再喂回同一局baseline，否则会重复累计；本批没有把它挂到任何客户端生命周期。read-only／tutorial来源即使带eligible标记也不产生达成。档案迁移、合格新事实证明、部分提交重试、旧检查点分支和跨页原子去重仍属于下一批，不能把这种纯函数幂等冒充已经解决持久化去重。

位置边界限正式经典15房／生存35房；重复／乱序位置、超范围层房、安全整数越界等明确失败。事实适配器输入必须来自原权威结算或已核验正文，不向原读取器增加绕过通道。

## 四、E01证据缺口保留

现行引擎没有保存精确四位未清零应得分。fact adapter允许未来权威证据通过独立参数传入；**当前真实事件里永恒六面骰清零且未提供该值时，分析返回unresolvedEvidence中的E01，不猜测、不授予**。合法证据为0不达成，正的正式四位值且确有清零才达成；C07不受此更严格条件影响。

这个参数不是新文件字段，也不是从用户JSON信任的领证通道。下一批需在评分阶段记录最小诊断证据，设计两模式编码、旧v5严格读取／恢复兼容与基线保护，不能仅从已舍入分项乘倍率还原。
