## 一、实现了哪些修改

### 1. 奖励选择失误

只在A、B奖励均可见、原模型估值差至少0.15时尝试，把原行动包的A/B投入交换；单行动换组，双行动必须整体交换，保持每份金额、行动类型、数量及真实总费用不变。

用原模型逐份报价效用比较原投入与交换后投入，只接受总预测效用下降的候选；轻微损失不超过0.35，中等不超过0.65。没有较差候选就不强行交换：原AI已经选低估值组时，不能把它“失误”成更好的选择。

这是**输出决策层的奖励选择偏差**，并未重写内部估值公式或伪造真实奖励；隐藏奖励不读取真实ID，也不参与该类交换候选。预测损失不是实际积分，双行动的预测单报价效用之和也不是完整对局收益模型。

### 2. 当前房间过度投入

只在本层还有后续房间、且不是BOSS房时尝试，提高同一行动包中1份报价，保留组别、类型与行动数量；必须使原模型预测效用降低，同时增加当前实际费用、减少后续可用资金。

| 限制 | 轻微 | 中等 |
| --- | ---: | ---: |
| 原金额倍数候选 | 1.30／1.45 | 1.60／1.80 |
| 最少新增实际费用／层基础资金 | 2.5%（至少1） | 5%（至少1） |
| 最多新增实际费用／层基础资金 | 10% | 18% |
| 修改后总费用／当前现金上限 | 65% | 75% |
| 单报价预测效用损失上限 | 0.40 | 0.80 |

不把非全押变成全押，始终通过真实费用、双行动和现金规则。这里允许突破原AI的**启发式节奏预算**，不突破游戏合法上限；否则仍只是在原预算里轻微改价，无法体现过度投入。

这是可观测的当前房间资金分配偏差，没有给未来凭空扣钱、修改层资金或重写完整跨房规划器；后续影响由真实引擎结算产生。

### 3. 触发与回退

- 概率维持25%／15%／5%／0%，有资金回合每AI每房1次机会，双行动不加抽。
- 新简单／标准在抽中后请求奖励45%、预算35%、旧报价20%；强度仍80%轻微／20%中等，二者相同。困难保持旧报价型5%，最高原版0%。
- 奖励／预算没有适用候选时回退旧报价型；中等可先退到同类型轻微。仍无合适行动则保持原行动，不用弃权或非法报价凑满概率。
- 请求类型、最终类型、回退与未生效分开记录。回退复用旧报价候选选择，不增加一次随机失误机会；主决策／报价随机流不受新增私有随机流影响。
- 基础行为仍由完整原版产生，保留主义、人格、角色道具真实效果；没有同时叠加现行低档planning／forecastError或此前能力削弱候选。

## 三、代码与复现边界

新增研究适配器使用现有显式research reducer；旧整局研究执行器只补可选transform，默认仍调用原报价失误函数。旧方案、数据和结果不覆盖；共享分析器只增加显式研究行身份支持，旧5400局和3600局的全部数值字段只读重算保持相同。

单元测试覆盖奖励真实费用不变、预算真实费用增加且保留现金、合法双行动整体换组、同种子确定性、最高／困难路径不变、秘密报价隔离、隐藏奖励不用于选组、输入不变、BOSS／末房不做预算失误，以及见证唯一性／类型／损失上限核验。人工构造的双行动夹具仅用于单元测试，不注入研究对局。

在仓库`web`目录顺序执行：

```powershell
npx --no-install vitest run lib/ui/achievements/classic-decision-mistake.test.ts scripts/classic-decision-mistake-plan.test.mjs --maxWorkers=1
node scripts/run-classic-decision-mistakes.mjs
node scripts/analyze-classic-decision-mistakes.mjs work/0.8/classic-mistake-study/content-<新目录>
```

默认普通测试跳过研究；运行器只分配新目录，run记录完整方案／来源逐文件SHA256／Node／平台／HEAD与dirty状态，收集前后核对来源不变。记录使用`research-only-decision-lapse`身份，不生成正式存档、回放或成长凭据。

`quoteAnalysis`仍保留失误前模型判断，实际改组／改价以独立before／after见证为准，不伪装成正式客户端已接入的新策略解释。本轮无浏览器实玩、版本推进、构建、commit／push、发布或部署。
