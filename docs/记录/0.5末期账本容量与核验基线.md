## 二、独立运行方式

在`web`目录：

```powershell
npm run report:ledger:corpus
npm run report:ledger:capacity
```

语料入口仍生成`corpus-随机串/`；容量入口生成`web/work/v05-closeout-ledger/capacity-随机串/`。报告用途与运行标记匹配，每次新建、排他写入，拒绝拿旧语料目录运行容量报告。失败时保留已完成的`case-构成-条数.json`及`status.json`，不会覆盖历史数据或拿部分结果冒充完整成功。

容量报告默认跳过，仅专用入口启用；独立600秒测试期限，不放宽普通测试／全局超时。Date固定为合成凭据的12:00 UTC以保持时间顺序，`performance.now()`保持真实；运行开始的实际时间、Node／V8／平台、Git来源与输入SHA-256单列。

## 三、采样矩阵与正确性边界

- 三种构成：经典、生存、混合／同根分支；0／64／256／2048／4096／8192／12288／16384，共24点。共同带200条历史、32KiB其他扩展及128个完成键（1计数＋127观察）。
- 先算模块／整档字节；超过896KiB模块或1MiB整档时，必须实际被正式读取器拒绝并明确标记超哪项，不继续报有效操作耗时。预算内读失败则算错误，不混成容量拒绝。
- 预算内读取、投影各3次，单条追加、整局31单元批次、重复追加各1次；64／2048／8192点另外测正式档案备份序列化／解析、生产gzip往返及内存适配器首次／重复保存。序列化／解析计时排除额外深比较断言，不测浏览器帧率或物理磁盘。
- 校对全部进度、达成时间、角色投影及输入正文不变；合成父分支、完整摘要及去重沿用正式校验，分支complete不重复算独立局。
- 精确1MiB可读、再多1字节拒绝；无余量时原档案不变、2条pending不提前确认。配额异常时同样保留，解除异常后只成功提交一次、重复不再次写。
- 2048成长＋8192完成键＋200历史＋32KiB扩展作为独立组合，是否容纳以本轮实际结果为准。16384条是数量上限，不承诺所有构成都能保存；16385条由codec上限回归单独拒绝。
- 内存只记进程heap快照，不强制GC、不称峰值；样本次数不是置信区间。模拟协调与配额异常不替代真实多页／物理配额验收。
