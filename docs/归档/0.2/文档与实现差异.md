# 文档与实现差异

> 名称维护：0.2.3起“妈妈的心脏”显示为“以撒的心脏”，“短程硫磺火”显示为“硫磺火宝宝”。下述原审计记录保留旧称，ID与规则未变，见 [图标与名称归档](../../开发/道具图标接入_v1.md)。

> 更新日期：2026-10-12；原七项审计结果保持不变。七项一致性核对均已完成。前五项修复记录于 v24，D04／D06 已按确认规则落实并通过回归，见 [v25](../早期研究/模拟报告_非叠加与福袋返款_v25.md)。

本文件保留审计原因与完成状态；各项的“修复前实现”是历史记录，不是当前行为。D04 属于规则明确化，D06 按正常竞拍返款的口径落实，历史模拟数据不回写。

## D01：尾巴效果没有排除尾巴自身（已修复）

- **设计要求：** [道具规范](../../规则/首批道具与结算流程_v1.md)规定嗝屁猫的尾巴不作用于该道具自身。
- **修复前实现：** [房间引擎](../../../web/lib/game/room-engine.ts)只检查玩家是否已持有尾巴，没有排除奖励 ID `guppys_tail`。
- **触发边界：** 已持有尾巴的玩家再次获得尾巴资格时，新尾巴也可能消失或翻倍。首次取得尾巴时尚未持有，因此不属于这个边界。
- **修复结果：** 在概率判定前排除尾巴奖励，首次／重复取得均为一份且不消耗尾巴判定随机数；其他奖励仍只判定一次。首次、多份持有、0／1／2 结果回归测试通过。

## D02：同房两组心脏的追溯加分没有合并乘算（已修复）

- **设计要求：** 妈妈的心脏取得当房即生效，各份积分乘数累乘。
- **修复前实现：** 每组奖励都以同一个原始房间分 `S` 计算额外加分，没有合并其他组心脏的乘数。
- **触发边界：** 同一玩家在终局房通过双扰乱与超凡升天取得 A、B 两组心脏，每组一份时，静态逻辑为 `S + S + S = 3S`；按两份心脏累乘的设计应为 `4S`。单组奖励中的多份心脏使用 `2^copies`，不是同一问题。
- **修复结果：** 发放结束后按玩家汇总实际取得的 `n` 份心脏，最终分为 `S×2^n`，只追加与原始分的差额；不重抽 D6／永恒六面骰，也不让其他新道具追溯生效。双组、尾巴翻倍／消失、已有心脏、更多选择摧毁及清零测试通过。

## D03：双行动候选没有过滤主义的零权重行为（已修复）

- **设计要求：** [主义规范](../../技术/AI主义模块_v1.md)将合作主义的扰乱高价设为硬禁用。
- **修复前实现：** 主行动保持零权重，第二行动却生成全部同模式候选；候选权重中的正基础项 `0.45` 使零权重行为仍可能被抽到。
- **触发边界：** 合作主义持有更多选择?、第一份扰乱后还有可行预算时，第二份候选中的扰乱高价仍可能被抽取。
- **修复结果：** 第二行动在生成报价前过滤主义基础权重及最终权重为零的策略；合作主义禁用项、显式关闭项与其他主义合法候选测试通过，保留储备、预算和停止追加。

## D04：部分道具的重复副本不产生额外效果（已明确并同步）

- **此前差异：** 实际功能只按是否持有生效，但文档未列非叠加例外、目录仍标为可叠加，AI 按可叠加方式估值。
- **确认规则：** 硫磺火、短程硫磺火和幸运脚明确为效果不叠加，不扩区间、不重复评分、不多发同组奖励。
- **落实结果：** [目录](../../../web/lib/game/item-catalog.ts)三项 `effectStacks=false`，文档与界面说明同步；现有 AI 非叠加逻辑使已持有后的再次获取估值固定为 `0.08`。
- **副本边界：** 仍允许重复获得，库存、道具数量和王冠惩罚正常计数。多副本计分／资格、重复估值、隐藏信息隔离及库存计数测试通过。

## D05：结算详情的分解值不包含心脏追溯加分（已修复）

- **设计要求：** 结算页的最终房间积分应解释玩家实际增加的总分。
- **修复前实现：** 顶部读取总分差，下方读取原始 `scoreBreakdowns`，两者对心脏追溯的口径不同。
- **触发边界：** 本房新取得妈妈的心脏时，两个标为房间积分的显示值可能不同；这不代表实际累计分漏加。
- **修复结果：** 新增 `roomScoreSummaries`，统一提供原始分、追溯追加分、最终分及追溯倍率；页面顶部与明细共同读取最终分，显示原始／追加分解。心脏、普通获奖、清零与全体观望的静态渲染测试通过。

## D06：福袋返款范围包含扰乱获奖行动（已落实竞拍限定）

- **修复前实现：** 按同组任意非观望行动返还 `75%`，包含通过超凡升天获奖的扰乱成本。
- **确认规则：** 仅正常竞拍实际获得福袋时返款；扰乱获奖只发放道具，不返款。
- **落实结果：** [房间引擎](../../../web/lib/game/room-engine.ts)只查找同组 `bid` 来源；没有正常竞拍来源时不生成福袋退款事件。
- **验证结果：** 正常／折扣竞拍、单／双扰乱、同组成本、尾巴消失／翻倍、更多选择摧毁和逐笔整数返款测试通过；保留双份返款可高于成本的规则。

## D07：伊甸初始木质十字架没有授予持久屏障（已修复）

- **设计要求：** 初始道具在第一房即可生效；木质十字架授予一层持久屏障。
- **修复前实现：** 初始库存只追加道具，没有像房间奖励一样为木质十字架授予持久屏障；入房准备只刷新神圣屏障临时层数。
- **触发边界：** 伊甸随机初始道具包含木质十字架时，库存中有道具，初始持久屏障却仍为零。
- **修复结果：** [运行时模块](../../../web/lib/game/runtime.ts)的 `grantItemInstance` 统一处理库存与屏障授予，初始道具和房间奖励共用；返款／心脏等上下文效果仍由房间引擎处理。第一房退款、持久屏障消耗不再生、跨层保留、神圣屏障不重复授予和临时优先消耗测试通过。

## 已澄清的实现边界

以下不是本次要改代码的事项，已经在现行文档中如实说明：

- 玩家数和房间数在规则对象中可配置，但客户端固定 19 个 AI 槽位、房间生成器固定五房与第三层终局例外；尚不是任意配置的完整对局框架。
- 早期行动页顶栏的排行、设置、规则曾为禁用占位；现已在选角、行动、结算及终局全部接通独立页面，排行只读公开信息，见 [客户端入口](./客户端功能入口_v1.md)。
- 宝箱问号估值采用 `0.52 × 长期周期修正` 的近似，不是实时遍历道具池计算数学期望；隐藏道具 ID 不进入估值。
- 基准线实现先将市场均值和常量分别保留四位小数，再计算并保存四位目标值；不是直到最终一步才舍入。
- 本地 Docker 构建与 Nginx 静态分发配置已存在，不代表云部署或正式发布流程已完成。
