# 0.3收口与0.4开发路线

> 日期：2026-10-13。当前应用0.3.10。用户要求提交v5更新并评估下一阶段。本文件是路线评估，不表示已升级为0.4.0或已分发。

## 一、版本判断

0.3已形成完整阶段：生存赛制与正式曲线、真人淘汰后AI续赛、四档AI与角色适配、实时榜与事实回放、生存教学、保存失败处理、长局稳定性与首轮优化、无损压缩、共享进度中心、统一v5文件与旧开发格式清理。

内容足以结束0.3的大功能追加，以0.3.10作为收口基线，下一批新功能进入0.4开发。不是仅按累计修改量更换版本号；0.4建议明确主题为**进度与长期记录**，首个相关功能闭环验证后再生成0.4.0。当前package／HTML仍为0.3.10，不在本次提交中只改数字。

阶段收口与分发就绪分开：已有1115项回归、11局44组文件还原、HTTP生产验收，仍不能代替直接file验收、真实浏览器容量或云端上线。不能说还有大量已确认未修复的P0故障；当前明确缺口主要是验收和真实实玩样本，若出现可复现阻断问题应优先修复。

## 二、P0：先完成收口验收和容量基线

|任务|已完成／真正缺口|完成标准|

## 三、P1：建议0.4.0首批主题

### 1. 长期完整回放库

当前已有按模式筛选的轻量完成记录，最多200条；每模式仅保留最近完整回放。这不是“没有历史页”，真正缺的是**多局完整回放的保留和管理**。

实施内容：当前v5回放入库、稳定索引与真正可用的回放绑定、按模式／角色／难度筛选、保留上限与空间提示、用户明确删除、导入／导出及同局去重。记录本体与大事实存储方式先依据P0容量实测决定，不能直接把更多1MB以上原文继续堆入当前键。

验收：多局并存、重启仍可读取、同局不重复入库、记录有回放才显示入口、删除一份不影响当前存档／其他回放／玩家档案；容量失败不阻止检查点保存。旧开发格式仍拒绝，不重启历史兼容工程。

### 2. 独立玩家档案备份／恢复

当前完整备份依附一份对局，没有可用对局时不能单独管理档案。把档案导入／导出接入进度，可在主菜单无局状态使用。

验收：独立档案预览和明确恢复确认、损坏／取消不变、无局可操作、当前两模式不被替换；现有完整备份默认不覆盖档案的语义仍保留。档案格式独立于对局v5和压缩容器1，新增文件用途须有明确契约与验证，不把档案伪装为续玩存档。

### 3. 进度统计完善

已有轻量结果可用于“已保留记录”统计。若增加总局数、存活率、角色／难度成绩等，先确定终局登记和持久计数口径；只读查看／重复导入不能重复计数。

验收：不将最近200条当作终身统计，累计计数与截断历史分开；未结束局不登记结果，存活／淘汰与排名使用权威终局，重导去重，备份还原不额外奖励。

首批可以按**回放库 → 独立档案 → 统计**交付小步版本，不要求一次完成整个0.4；0.4.0不需要先填成就空页面。

## 四、P2：后续校准与玩法扩展

- **AI／角色实玩校准：**标准与困难已有改善，但困难／最高接近、简单仍有团灭样本；雅阁和以扫双行动、阿撒泻勒及合作／混乱主义仍需独立样本。冻结最高和正式曲线，不自行上调线或补钱兜底。
- **教学细化：**已有生存六课，按实玩反馈补真实角色报价场景与术语，不重复当作未实现。
- **成就／角色解锁：**先定义目标、条件、进度、奖励及是否影响角色可选，再接入持久档案。预留字段不代表功能已完成，也不是0.4.0前置。
- **生存紧凑事实编码：**压缩已完成；引用／差分编码仅在实测证明必要时设计新编码版本，不删随机／评分／淘汰事实，不覆写survival-facts-1。

## 五、后置范围

移动端／触控／真机、孤注一掷恢复正式池、任意人数／层数／资金配置、回放自动播放和历史分支恢复继续后置。云端分发是否启动按发布需求单独推进，不把源码提交当作上线。当前只有一个人类玩家加浏览器AI，不在此路线中暗示已做联网多人。
