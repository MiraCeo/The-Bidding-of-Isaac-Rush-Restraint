## 一、已接入的入口

主导航：游戏／排行／进度／设置／规则。主菜单、未开始选角、经典和生存的行动／结算阶段均可进入同一个进度中心。

进度使用三个二级标签，不模拟文件管理器或多存档槽：

- **总览：**经典与生存各一张当前对局卡，展示角色、阶段、层／房、保存状态；可继续、查看终局或进入选角。真人淘汰后显示AI续赛中。
- **对局记录：**按经典／生存筛选；提供实际存在的本局和最近回放入口，显示独立玩家档案中的最多200条轻量完成记录。累计分数、名次、存活／淘汰层与难度沿用原数据，不把保留条数称作生涯总局数；没有数据的历史不能假装能播放完整回放。同一生存终局的本局／最近记录不重复列两张卡。
- **存档与备份：**按模式选择，搬入原续玩、回放、完整备份与导入预览。两模式文件读取仍可自动识别真正模式，不把选择的标签当作文件身份。压缩下载、原JSON读取、损坏／取消保留、备份默认不恢复档案和明确确认沿用原实现。

成就／角色解锁还没有明确规则或实现，仅在总览说明未来开放，不开放空标签、伪造完成度或自动发奖励。每种模式仍只有一份自动续玩存档；尚未建设本地多存档槽、长期完整回放库或独立档案备份。

## 二、设置与对局状态

设置只保留显示偏好、恢复默认显示、版本与更新；存档／记录功能已迁出，不保留第二套入口。

生存行动页的完整状态条只在实际游戏内容上显示；结算页的设置／规则也隐藏大状态条和构筑／回放／重新选角工具行。顶部简短对局上下文及返回游戏保留。游戏及榜单的计分、斩杀线、继承／兑换数字未修改。

## 三、状态与返回不变量

- 权威经典会话继续由ClassicGameApp持有，生存会话继续由GameApp持有。进度中心共用只读会话快照与现有操作接口，不能重新创建第二套游戏或提交命令。
- ClassicGameApp即使当前视图不显示也保持组件及会话；稳定memo／callback发布当前接口。只切换展示页面，不重新初始化引擎。草稿保留原值，DOM输入节点允许随视图重建。
- 两模式未开始时的角色选择提升到现有模式控制器，进入／离开进度不丢选择，也不自动开局。显示偏好仍与对局分开保存。
- 真人淘汰后原25ms分步AI续赛继续运行，不因进度页被打开而暂停、造真人行动或改变参数。
- 生存完成档案写入后通知进度刷新；完成回放及档案错误分别保留，不把失败数据清空。文件面板接收最新最近回放，避免AI完成后需重开才能查看。
- 从进度打开回放后返回原进度分类和模式；保留来源模式，不改变活动模式存储标记。随后继续某个模式才明确切换对局。只读回放不保存为当前局、不登记奖励。
- 顶部导航可从进度进入设置／规则／排行，使用一次性UI导航请求，不改变游戏阶段。Esc从导入／备份先退出任务，从进度打开的回放返回进度，不跳过确认。
- 更换分类／模式或离开进度会取消未完成读取和导出，迟到结果不安装预览；当前局、另一模式存档和档案保留。

## 四、下一批：当前协议与兼容清理

用户已经同意不再维护开发期旧v2/v3兼容。本批为了单独验证UI迁移，**仍保留现有内层经典v2/v3、生存v4及压缩容器1**，没有宣称兼容已删除。

下一批先建立明确的当前文件头／模式／用途，再改两模式读写、自动存储、导入预览和压缩往返；随后移除历史读取／迁移分支及对应兼容测试。不能直接删当前经典v3解析器使经典功能失效。原游戏算法与固定状态回归继续保护，不需要为了换文件头重写AI／计分。旧开发文件保留本机资料，不静默清除、自动覆盖或混用当前默认参数。

保留独立协议变更提交／验证边界；记录旧格式明确拒绝、新当前格式导出—落盘—还原、两模式五阶段与完整备份往返、取消／配额错误的数据保留。长期回放库、独立档案备份及成就仍在之后实施。
