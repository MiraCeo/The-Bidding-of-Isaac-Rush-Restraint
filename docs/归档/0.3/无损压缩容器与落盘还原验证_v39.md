# 无损压缩容器与落盘还原验证 v39

> 日期：2026-10-13。应用0.3.8，接续仅研究的v38，正式接入文件导出／导入。下载仍为.json；内层经典v2/v3、生存v4、survival-facts-1、AI、曲线及存储键不变。

## 一、实现与用途

经典与生存设置的续玩、回放、完整备份，以及两类回放页的直接导出，统一使用无损压缩。先生成原协议JSON，再使用浏览器原生CompressionStream(gzip)压缩其UTF8字节；gzip数据编码为Base64并装入JSON容器。不去重、裁剪、舍入或删除事实，BOM与原文本均保留。

容器独立版本1：

```json
{
  "format": "the-bidding-of-isaac-compressed",
  "version": 1,
  "compression": "gzip",
  "encoding": "base64",
  "originalBytes": 12345,
  "sourceChecksum": "八位十六进制摘要",
  "data": "Base64 gzip数据"
}
```

版本1只允许这些字段。originalBytes是**原文UTF8字节数**，不是JS字符串长度；sourceChecksum沿用shortHash文本摘要，gzip另有原生完整性校验。两者用于损坏检测，不是签名。文件用途、模式、难度、引擎及规则身份只由内层原文件决定，外层不另存一套可能冲突的元数据。

导入流程：外层JSON大小／结构检查 → 自动识别容器 → 有界流式解压 → 字节数、UTF8、文本摘要检查 → 原JSON结构检查 → 原模式分发及原严格解析 → 预览 → 明确确认。只读回放仍不运行AI；检查点仍按文件原引擎重建，不因解压换成当前默认。备份默认不恢复玩家档案，勾选才恢复，沿用原成对写入／失败回滚。

无原生压缩能力时导出原JSON，并给出实际格式提示；压缩后反而更大时也保留原JSON。无解压能力时不能读取容器，但原JSON仍可读取。**0.3.7及更早HTML不能直接读取新容器**；本批保留的.original.json／.restored.json可用于旧版诊断，能否续玩仍取决于原引擎兼容。

本次只压缩**手动导出的文件**。localStorage检查点、最近回放、玩家档案继续原格式，不做自动迁移；下载变小不代表浏览器自动存档配额扩大，也不代表回放绘制变快。

## 二、大小上限、取消与失败

- 压缩文件和解压原文分别限制8MiB；流式累积实际字节不能超过声明长度或原文上限，不只检查容器头。
- 解压后的原JSON继续限制深度32、节点100万，以及原协议中的命令、实例、名册、金额和语义边界。
- 未知版本／算法／额外字段、非法Base64、gzip损坏或截断、UTF8错误、长度／摘要不符及嵌套容器拒绝。解压成功不豁免原文件篡改校验。
- 异步文件读取／解压可以取消；取消、更换文件或卸载面板会中止任务，迟到结果不安装预览。导出期间按钮防重复，卸载／取消中止尚未下载的任务。
- 下载成功提示包含压缩前后KiB；表示浏览器已请求下载，不把它说成用户磁盘保存已确认。
- 失败和取消不替换当前局、不覆盖玩家进度或自动保存，不登记只读文件奖励。

实现入口：web/lib/ui/compressed-file.ts、mode-data.ts、json-download.ts；研究引用编码仍在research目录，无客户端依赖，未接入正式协议。

### 浏览器复验发现的原备份边界

七层压缩检查点和独立回放可读取，但Node生成的完整备份在浏览器被旧的精确对象比较误拒绝。诊断确认：原文成功逐字解压，两份内层文件分别通过校验；差异仅在重建回放中未舍入的妈妈的刀`additive_score`说明金额，例如16.916221361144007与16.916221361144004。来源是跨JS运行时Math.exp的末位浮点差异，不是数据缺失或压缩误差。

本轮仅在备份的“原回放与检查点重建回放”配对比较中，允许同房／同玩家／同触发索引、同itemId和kind的刀具说明金额相差至多`8 × Number.EPSILON × max(|a|, |b|)`。其他字段仍精确比较，包括所有权威四位分数、资金、行动、随机结果、身份、顺序与终局。只调新建的预期比较对象，不修改原文、校验摘要、已记录回放或计分引擎；对正常文件导出大小不产生变化。

3项专门回归覆盖正负末位差异、1e-9的更大差异（内层事实与双摘要可通过但配对仍拒绝）、改道具／触发顺序／正式分数拒绝。不将其扩大为全文件浮点容差，更不放宽检查点权威状态一致性。
