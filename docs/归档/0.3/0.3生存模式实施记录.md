# 0.3生存模式实施记录

> 更新日期：2026-10-13。0.3目标已获准分步实施；当前可游玩客户端仍为0.2.13。本文件记录新开发范围，不改写0.2研究与交付历史，不表示生存模式已经开放或0.3.0已经发布。

## 一、范围与确认项

目标是在保留经典三层十五房、角色与单房竞拍机制的基础上新增生存模式。采用最小必要改造，不新增自定义编辑器、解锁／成就、联网或大规模道具池；移动端仍后置。

已确认的生存流程：

- 初始20人，每层五房，第五房仍为BOSS；每层公共基础资金1000，角色与经济效果另外计算。
- 每层至少淘汰2人，淘汰后剩余人数小于等于6时立即终局；允许直接降到6人以下，不补人。
- 未过线者至少2人时全部淘汰；只有1人不过线时，再补淘汰过线者中最低分者；全员过线时淘汰最低2人。
- 真人提前淘汰后，不再提交或参与后续经济与竞拍，由AI自动完成整场比赛。其个人出局与整场终局必须分开记录。
- 只要未结束层满足最少淘汰数，最长为`ceil((20-6)/2)=7`层、35房。这是规则推导，不是另加的强制层数上限。

资金兑换10%、上一层生存分继承20%按已同意方案试行，仍需模拟验收平衡。斩杀线尚未指定，代码不得设一个隐含默认值。

2026-10-13进一步确认并在第三步实现：

- 生存暂时取消黑王子之冠：奖励池与真人／AI伊甸随机初始道具均排除；经典道具、倍率与旧回放不变。
- 同分淘汰在边界并列组中使用对局种子随机补足名额，保存实际决胜数值；全员不过线全部淘汰，以团灭结束，无冠军。
- 最终累计积分为各层房间分与余额兑换分之和；继承分不重复累计。原房间加算／倍率先完成，不再次作用于兑换或继承；积分保存四位小数。
- 总榜包含全部20人：存活者优先；淘汰者先按淘汰层数降序，再按截至淘汰的累计积分降序。同组同层同分用种子随机决胜。
- 存活者淘汰层字段保持null，展示“存活”，不是虚构一个淘汰层数；淘汰者展示“第X层淘汰”。团灭仍有总榜第一，但不授予冠军。
- 生存每层第五房按正常BOSS池抽奖，不复制经典第三层固定双心脏例外；心脏BOSS倍率及当房追溯保留。
- 旧v2／v3只读回放继续读取，旧经典检查点继续经典，不转换为生存；独立玩家档案与显示偏好保留，读取失败保留原记录。

主菜单／设置导入、结果页／回放界面及完成记录的档案展示尚未接入，不能因为内部规则或v4协议已完成而写成生存UI已经开放。

### 积分计算契约

调用方必须提供全部五房的**最终房分**，已包含道具计分和心脏追溯；第一层上一层生存分传0。

```text
房间分 R = 五房最终房分之和
兑换分 E = round4(实际层末余额 × 0.1)
继承分 I = round4(上一层生存分 × 0.2)
本层新增分 N = round4(R + E)
本层生存分 S = round4(N + I)
```

分别存储展示组件，避免界面精度参与比较。资金必须为非负安全整数；原房分、上一层分和斩杀线必须符合声明的存储精度。非有限值、负值、越过安全存储精度的数值报错，不静默截断、归零或加兑换上限。

`newScore`只用于区分本层新增与递归继承；本步没有实现或定案最终累计排名，不应用王冠，也不再乘房间道具倍率。余额不在本函数中扣除，后续编排必须保证层末只结算一次，并在换层执行既定资金重置。

### 淘汰计划契约

只接收当前存活者的身份和生存分，斩杀线由调用方显式传入：

- 已确定的普通结果返回`resolved`、淘汰原因、实际存活名单及是否终局。
- 最后淘汰名额横跨同分组时返回`requires_tie_break`，记录确定淘汰者、并列候选和所需名额，不以ID／输入顺序偷偷决定人选。
- 全员不过线时返回`requires_all_below_policy`，不擅自保留最高分者，也不擅自生成冠军或团灭终局。
- 待定结果没有可应用的存活名单，不能把其中的确定部分先写入游戏。
- 已小于等于6人的状态不再执行新一轮淘汰；空名单不是合法的层末输入，不能借此绕过团灭待定。

内部参数约束最少淘汰数不得超过终局人数阈值，避免调参后仅靠末位补足就清空最小的未结束名单。全员不过线的赛制例外仍独立待定。

### 生存内部流程

[survival-session.ts](../../../web/lib/game/survival-session.ts)目前可通过内部API运行：

```text
房间行动 → 房间结算 → 下一房
                      └第五房结束→层末结算
                                  ├普通淘汰已解决→下一层
                                  ├剩余≤6→competition_complete
                                  └同分／全员不过线→显式待定，不推进
```

- 只生成已到达层的五房；角色资金、利息、项圈、屏障和偷钱袋共用现有单房／入房规则。
- 完整20人名册保持身份和顺序，活跃集合单独维护；经济、AI、市场和奖励只处理当前活跃者。出局者的资金、积分、库存、屏障与AI历史冻结。
- 层末只在第五房已经完成全部结算后处理，重复提交／错误阶段命令不追加事实或重复记账；已解决的层末更新递归生存分，待定结果不先应用部分淘汰。
- 真人出局后，`continueSurvivalAfterHumanElimination`自动执行AI房间和层间推进，无伪造真人行动。遇到待定机制停在层末；其推进命令预算由规则上界推导，异常时报错，不能据此强行结束或选冠军。
- 市场样本率使用当前活跃人数作分母，仍是有效行动样本口径，双行动可能超过100%。
- 单房发奖允许显式传入全局取得顺序下界，避免最高编号道具持有者被淘汰后，新实例取得序号倒退。经典不传此参数，原编号行为不变。
- 房间记录保留实际入房事件、活跃名单、AI策略、提交、扣款、原始／追溯／最终房分及奖励；层末记录保留分项、斩杀线和淘汰计划，为下一步事实协议提供输入，不反推原事件。
- `survivalPublicStatus`只投影层／房／人数、当前斩杀线和真人公开数据；不暴露隐藏奖励、私人AI预测、秘密行动或完整未来配置。

### 实验参数与未完成边界

本步不是正式开放生存模式：

- 必须显式传入覆盖所有可能层的内部斩杀线计划与BOSS奖励策略，代码没有默认斩杀线。测试中的0和高斩杀线均为测试输入，不是正式设计数值。
- 房间生成器新增`classic_final_hearts`／`standard`显式奖励策略；经典默认仍为第三层双心脏。生存测试显式选择标准BOSS池，并未替设计方确认正式生存奖励策略。
- 生存原型暂用旧AI启发式验证流程；整局剩余房间输入仅为公开规则推导的上界，不是实际未来终局知识。斩杀线压力、兑换机会成本、相对末位风险等专属AI尚未实现，也不因此宣称平衡已验证。
- `competition_complete`只表示淘汰赛已达到结束阈值，**没有最终排行榜、王冠计算或冠军**；这些仍需按待定积分口径实现。
- 新存档／回放协议、恢复迁移和主菜单／层末UI尚未接入，原型不进入旧v3文件或玩家档案。
