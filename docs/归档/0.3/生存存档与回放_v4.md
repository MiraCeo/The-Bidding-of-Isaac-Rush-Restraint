# 生存存档与回放 v4

> 历史文件规范：0.3.10起当前经典／生存对局文件统一v5，旧v2/v3/v4不读取或自动迁移。现行边界见 [当前协议v5](../../技术/当前文件协议_v5.md)；以下保留原阶段定义与验证。

> 日期：2026-10-13。0.3.4开发预览完善生存回放界面；v4事实编码不变，新分层对局使用client3，旧client2无难度对局保持最高基线续玩。经典继续写v3、读v2／v3，数据结构和兼容标识不变。

0.3.4展示改进见 [生存回放界面完善](../../技术/生存回放界面完善_v1.md)：本房个人／全场、整局图表、层末账本及保留总榜。共享经典组件的适配记录只是显示投影，不导出为经典v3，不补造淘汰者行动。累计图仅聚合已发生R与已发生兑换，未结算层无兑换；终局数字保持原事实。

0.3.8新增独立版本1的无损gzip传输容器，设置／回放文件导出默认压缩.json，读取自动识别容器或原JSON；解压后仍按下述原v4严格校验。没有改变survival-facts-1、引擎身份或自动存储，详细边界及六局落盘验证见 [v39](./无损压缩容器与落盘还原验证_v39.md)。旧HTML不能直接读取容器。

## 一、模式与版本边界

- 文件format沿用`the-bidding-of-isaac-save`／`the-bidding-of-isaac-replay`，但生存文件必须显式声明`version:4`与`mode:survival`。
- v4缺失模式字段不是经典默认值；旧v2／v3仅由原经典解析器处理。
- 统一入口 [mode-data.ts](../../../web/lib/ui/mode-data.ts)用于两模式设置，区分经典文件、生存检查点、完整备份和事实回放；预览后确认才载入。
- 应用0.3.2。release-config的v3继续描述经典协议，版本面板另明确生存v4／survival-client-3，不混用经典兼容标识。

## 二、生存规则身份

0.3.6新局显式参数`aiPolicy:role-aware-1`与难度共同参与指纹，使用survival-client-4；只有新标记局启用低档改进。旧client3缺少aiPolicy保持原四档函数、参数与身份续玩，旧client2缺难度保持最高；旧client1仍只读。最高在新旧族始终原AI2，仅新规则身份携带策略标记，不改变真实行为。v4和survival-facts-1编码不升级，未知策略或策略标记缺难度拒绝。

[survival-record.ts](../../../web/lib/ui/survival-record.ts)新局使用`survival-client-3`，参数新增`aiDifficulty:easy|standard|hard|highest`，难度参与兼容指纹与对局ID。历史client2缺少该字段，保持原结构、身份和原最高策略续玩，不自动添加字段；client1事实回放仍可只读。参数、完整单房规则快照、有效道具／角色定义及赛制语义参与指纹；同种子、角色但不同引擎／斩杀线／难度不混为一局。

旧client1检查点或完整备份不由新AI续跑；兼容检查在重算前失败，保留原文件与自动数据，菜单／导入页显示原因。旧回放读取不执行新旧AI。新检查点恢复保留自身记录的曲线，不将其改为当前默认。冻结旧策略生成的client1权威事实、重算摘要与只读／拒绝续玩边界由专门测试保护。

`survival-facts-1`采用 [冻结语义表](../../../web/lib/ui/survival-facts-v1.ts)：正常BOSS抽奖、无黑冠、种子同分淘汰、团灭无冠军、存活／淘汰层／累计分总榜、不重复累计继承。这张表是历史编码契约，不随未来默认配置修改；以后改变这些机制须新增编码与读取路径。

正式入口斩杀线为200／325／500／750／1050／1500／2500，新局默认标准难度。恢复保留文件自身的曲线及难度，未知难度拒绝；只读client1标“未分层（旧AI）”、client2缺省标“最高”。人数20、每层5房、基础资金1000、至少淘汰2人、结束阈值6及4位存储精度不随难度改变；内部研究参数不是玩家自定义入口。

## 三、续玩检查点：严格重建

[survival-persistence.ts](../../../web/lib/ui/survival-persistence.ts)提供`serializeSurvivalCheckpoint`／`parseSurvivalCheckpoint`。

保存内容：

- 种子、角色、规则事实与明确模式身份。
- 初始及当前构建身份。
- 所有被接受的阶段命令及每条命令的实际构建身份。
- 当前权威状态、层末记录、全员冻结名册、存活集合、AI档案／历史、资金、房间累计分和生存累计分。
- 真人报价草稿；无真人行动资格或非行动阶段不能附带草稿。

大型逐房事实与AI诊断不重复写入检查点，读取时在**脱离当前对局的状态**上重建。包括真人淘汰后的`submit_ai_room`命令，而不是伪造真人观望。按种子复算AI、房间经济、同分决胜和终局总榜，逐项比较状态与接受命令；重复、未知、错阶段、非法报价、篡改状态或非当前规则均拒绝。

最大接受命令数由规则推导：7层×(每房提交／推进各1次，加每层推进1次)=77；这是校验上界，不是另加的玩法结束条件。原构建身份保留，新构建继续后只标记新产生的事实，不回写早期来源。`completedBuild`单独保存实际终局来源，已结束的对局在新版程序查看／导出时不会把终局标成新构建。

检查点不是只读回放，也不是玩家档案备份。独立档案不在此协议中重置或登记奖励；完整生存备份和设置确认交互后续接入。

## 四、只读事实回放

`createSurvivalReplay`只收集已发生的结果：

- 初始公开玩家快照和入房经济事件。
- 已结算房间的活跃名单、真实AI策略、行动、四种金额、市场基准线、原始／追溯／最终房分、奖励、道具实例与事件。
- 每层的房间分、余额兑换、上一层分及继承、当层新增分／生存分、斩杀线、同分决胜数值、淘汰原因与实际剩余名单。
- 整场终局的冻结20人名册、累计新增分、存活集合、淘汰层数、总榜、终局原因与可空冠军。

不保存未来房间奖励、未提交报价、私人AI预测或续玩命令。当前仅结束一房或处于BOSS已结算但尚未结算层末时，也能导出部分事实；未结束局没有最终总榜。

`parseSurvivalReplay`校验编码、参数、身份、动态房间／层数、活跃集合、金额账本、实例追加、房分、递归继承、淘汰及排名的内部一致性；**不调用启动、AI、RNG、单房结算或推进，不写浏览器存储和玩家档案**。

历史引擎身份只要使用已支持的事实编码并保存完整规则上下文，仍可只读查看；不能因此用当前引擎续玩。解码只消费保存的权威评分值和实际随机结果，不以当前道具估值或新AI覆盖旧事实。

## 五、榜单与同局比较

[survival-view-model.ts](../../../web/lib/ui/survival-view-model.ts)提供只读结果投影，状态显示“存活”或“第X层淘汰”。无冠军团灭榜不会把第一名误标为冠军。

同局比较除模式ID与规则身份外，还比较完整结算事实；仅忽略兼容的构建来源差异，不忽略分数、淘汰、随机决胜或榜单。不能只靠种子或短摘要判定同局。

## 六、存储与文件边界

0.3.5区分检查点与完成回放保存结果：先写检查点，成功后尝试较大的归档；归档失败保留旧归档且仍可刷新恢复终局，提示导出当前回放。检查点失败时不覆盖归档，提示浏览器可能保留较早进度。`saveSurvivalProgress`返回两项结果，原boolean保存入口仍表示两项均成功；协议与数据身份不变。

- 活动检查点：`bidding-survival-checkpoint-v4`。
- 最近完成回放：`bidding-survival-last-completed-v4`。
- 与经典存储键、独立玩家档案及显示偏好隔离。读取失败不删除原记录；写入失败返回失败，不修改内存对局。
- 文件上限8 MiB，限制嵌套深度、节点规模、记录数、实例数和字符串长度；校验数值、字段与模式，不接受非有限值或未知命令。
- 文件摘要用于发现内容变动；事实回放仍做完整一致性校验，续玩仍严格复算，不把摘要相符当作语义正确。
- 当前v4采用有界完整事实快照，不复用要求固定名单长度的v3差分编码，也不冒充已有Gzip支持。长局容量优化可在实际测量后推进。

本轮原始验证与HTML构建信息见 [0.3实施记录](./0.3生存模式实施记录.md)，旧经典说明见 [存档v3](../0.2/构筑与存档_v3.md)、[回放v3](../0.2/逐房回放_v3.md)。

## 七、完整备份与独立完成记录

`kind:backup`封装相互一致的生存检查点、已结算事实回放和独立v1玩家档案，逐份检查内外摘要和完整事实，不接受错配。同一设置入口支持读取；备份中的玩家进度默认不恢复，必须明确勾选。

自动完成登记仅消费实际完成会话的事实总榜，使用完整事实SHA256身份去重，忽略纯构建来源差异。历史项带`mode:survival`、实际排名、累计新增分、存活状态和淘汰层数；保留旧经典历史和扩展数据，不新增解锁／成就规则。只读回放不写入档案。

活动模式提示另存`bidding-active-mode-v1`，不是对局协议的一部分。生存完成检查点保留用于结果页恢复，最近完成回放单独保存；确认重新选角只清当前生存检查点，不清经典、历史回放或玩家档案。

0.3.5备份显式勾选恢复玩家进度时，先准备合法检查点和档案，再写入对应两键，第二步失败回滚先前写入并保留当前内存局。浏览器连回滚也拒绝时明确提示存储未恢复，要求导出内存原局，不冒称事务绝对原子。仅载入对局仍允许存储不可用时在本页运行，失败提示不会被载入成功遮挡。清除旧检查点失败不进入新选角，防止刷新恢复被误认为已放弃的旧局。跨模式只读回放返回来源模式，不改变活动模式标记；返回房间阶段保留草稿，不承诺重开原设置子页。
