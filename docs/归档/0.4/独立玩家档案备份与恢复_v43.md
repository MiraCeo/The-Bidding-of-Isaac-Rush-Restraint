# 独立玩家档案备份与恢复 v43

> 日期：2026-10-14；应用0.4.2开发预览，基于已提交并推送的59eda80。属于0.4数据管理整理，成就与解锁仍留在0.5；本批未提交。

## 一、入口与实际范围

进度→存档与备份→独立玩家档案，两种模式共用；主菜单没有对局时也可使用。不依附当前局或最近回放，不更改模式、选角、草稿、资金、积分、AI续赛、显示偏好或IndexedDB完整回放库。

- 导出读取当前可核验档案并生成独立文件；没有保存过档案时可明确导出空档案，不自动写入占位资料。读取失败／本机原文损坏时不会导出加载器的空档案替代值。
- 读取支持当前独立档案文件的原JSON与无损压缩容器1；先校验和预览，本机／文件各显示创建时间、更新时间及经典／生存轻量记录数量。
- 恢复默认不勾选，必须确认“用文件档案替换本机档案（不合并）”，再点击确认恢复。只替换档案，不恢复对局、不合并、不重新登记文件成绩；原文件不修改。
- 本机原文损坏但仍可读取时，保留原文直到用户明确用有效备份替换；读取本机存储失败则不能建立确认基线。坏输入、取消或标准存储写入失败不替换原资料。
- 原文件读取或压缩支持取消，Esc、模式／分类变化及离开页面丢弃迟到结果。恢复是同步单键写入，不先删除旧档案，不引入第二份自动缓存或静默清理。

已保留历史最多200条，不作为终身总局数。档案扩展字段原样保留，但不在此处发放成就、解锁或改变角色可选范围；累计统计仍未实现。

## 二、协议与数据边界

新增外层`the-bidding-of-isaac-profile-backup`，version1、kind=`profile-backup`，含导出时间、构建来源、profile正文及checksum；没有游戏mode或session。档案正文仍`the-bidding-of-isaac-profile` version1，localStorage键仍`bidding-player-profile-v1`。对局v5、压缩容器1、回放库schema1和其他存储键不变。

复用现有JSON结构／摘要检查、profile1语义校验和gzip有界解压：传输与解压后文件仍最多8 MiB，档案正文仍按既有1 MiB规范大小约束，完成历史最多200条。拒绝未知协议、用途错配、额外外层字段、非法日期／数值、危险键、损坏摘要、过量历史／扩展树和无法解压的输入。不把NaN／Infinity先转成null再接收，不自动读取旧对局格式。

对局文件入口遇到独立档案给出明确入口提示，在游戏恢复／AI重建前拒绝；独立档案入口也不把续玩、回放或完整备份当作档案单独载入。旧完整备份默认不恢复档案、成对恢复及失败回滚语义保留。

## 三、预览失效与刷新

预览完成后捕获当时本机档案的原始文本。AI续赛或其他页面写入新档案后，显示当前状态更新与旧预览失效，原确认不再可用；“重新核对本机档案”更新比较快照并要求重新勾选。即使更新通知尚未展示，确认函数也会在单键写入前重新读取并比较原文，不以旧预览覆盖已观察到的新记录。

本页档案写入发出安全通知；经典会话工具、共享进度与档案面板订阅本页通知、对应storage事件及重新聚焦。观察者读取实际存储，不相信事件传入的正文，不为刷新修改游戏状态或重存对局。通知传递失败不改变已成功的保存结果，标准额度失败也不伪报恢复完成。

这是单次localStorage写入加预览原文检查，**不是跨进程原子CAS，也没有给所有既有写入新增全局锁**；同时在其他页面推进不同对局的全局事务与累计去重仍属于后续数据基础工作。已完成单页AI续赛期间保护和真实跨页面更新观察，不把它称作全部并发一致性问题已经解决。[Web Storage标准](https://html.spec.whatwg.org/multipage/webstorage.html)、[setItem接口](https://developer.mozilla.org/en-US/docs/Web/API/Storage/setItem)是接口边界依据。

总览／轻量历史在档案读取报错时显示无法核验，不把读取失败解释成零条记录。此项是显示与文件处理整理，不改实际完成登记算法或终身统计口径。
