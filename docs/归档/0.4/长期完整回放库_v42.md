# 长期完整回放库 v42

> 日期：2026-10-14；开发预览0.4.1，基于0.4.0只读存储诊断。当前尚未提交。游戏规则、AI、最高难度、角色、曲线、四位积分和随机流均不变。

## 一、入口与使用

进度→对局记录→长期完整回放库。经典／生存共用库，列表跟随模式筛选，另按角色、生存难度及已完成／进行中片段筛选；从回放返回保持原分类、模式与筛选。轻量完成历史单独默认折叠，仍最多200条；不因导入或查看回放记为实际游玩，也不是终身统计。

- 当前权威对局结束后独立异步归档，不等待库保存才写原检查点或登记结果。新局开始不会清空库；只读文件不会触发自动归档。
- “本局回放入库”可手动重试或保留进行中片段；片段明确无终局成绩。最近完成回放可手动入库，旧缓存不自动迁移。
- 导入只接受v5回放／压缩容器1，先校验和预览，确认才写库；续玩、备份和旧版本在进入严格重建前拒绝。取消、迟到结果与离开页面不会写入尚未确认的候选。
- 查看只读取已存事实，不运行AI／随机数或恢复对局。逐份导出使用已验证的库文本，解压后仍是首份原JSON，含BOM与原来源。当前没有整库批量容器。
- 删除前显示具体角色／种子和明确确认，只删除这一份库记录；续玩、最近回放、其他库记录与玩家档案保留。不可撤销的删除不自动执行，满库也不自动删除。

## 二、存储与失败边界

原localStorage各模式检查点、最近回放、草稿、档案和偏好不迁移，不新增大文本键。独立数据库`bidding-replay-library-v1`，schema1三张表：`index`轻量元数据；`payload`gzip容器1或原JSON；`removed`小型删除标记。索引只查询元数据，不解压所有回放。

默认最多100份回放、合计64 MiB已存UTF8文本，两模式与片段共享上限；不包含数据库物理开销或删除标记，不当作浏览器配额承诺。浏览器可能提前拒绝写入。库是当前浏览器与来源的本地资料，不等于外部文件备份；不跨端口或HTML文件位置自动同步，也不申请持久存储权限。

编码、校验和SHA256在事务前完成；单一读写事务内检查去重与上限，索引与正文共同提交，以事务完成而非请求成功判断入库完成。并发连接不会冲破上限或出现半份记录。失败保持旧记录，没有清库、降级覆盖、旧格式迁移或自动淘汰。不可用、打开超时、被旧页面占用、未来schema、损坏索引／正文均保留原数据并如实显示，继续游戏和原文件功能独立。

删除同时移除索引与正文并写小型标记，避免当前终局刷新后又自动占回空间。只有用户手动保存或确认重新导入才移除此标记。标记不包含回放正文，首版不提供标记批量维护。

库操作后即时刷新；重新聚焦页面或点击刷新可读取另一页已提交记录，不使用只存在内存的假库。读取时校验正文SHA256、当前文件校验、原始大小、元数据和事实摘要；损坏的同键旧正文不被新的导入静默覆盖。

实现遵循[IndexedDB事务生命周期](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction)：不在活跃事务里等待gzip／摘要Promise；短连接在事务结束和versionchange关闭。测试依赖fake-indexeddb仅为devDependency，不进入客户端包，也不把它称作原生浏览器磁盘验证。

## 三、去重与事实保留

模式＋SHA256完整事实投影作为键，不单凭种子、名次或回放ID去重。相同事实换构建来源／导出时间保留首份文件；同种子不同报价分支、难度、角色或正式计分事实分别保留。原始正文无损，不丢房间、层末、淘汰或奖励事实。

真实Chrome155与Node既有35房样本比较发现：检查点恢复后只有35处妈刀`scoreBreakdowns.triggers`的未舍入说明金额出现约1e-15～1e-14尾数差异，正式四位房分、资金、淘汰与终局结果一致。初版严格全字段摘要因此误分两份。最终仅在库的去重投影中将`moms_knife`＋`additive_score`说明金额归一至8位小数；其余字段仍逐值精确，正式四位积分不归一。不同投影保留为不同记录；去重保留首份原始尾数，不重写文件，也不改变玩家完成键或其他比较函数。增加微尾数同键、说明金额实变异键及正式分数变化异键回归。

隔离比较研究脚本`scripts/build-replay-library-study.mjs`只读取项目生成的v5样本，原生页面不读取／删除用户存储、不下载文件。原差异报告`web/work/replay-library-cross-runtime-before.json`保留；修正后跨运行时键与最终浏览器库验证在下节追加。
