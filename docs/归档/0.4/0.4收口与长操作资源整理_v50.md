# 0.4收口与长操作资源整理 v50

日期：2026-10-14；开发预览0.4.9。按用户要求先收口，布局建议稍后提供，本轮不修改CSS、布局层级、导航或表格样式，也不提前开展0.5成就／解锁。

## 一、本轮完成范围

### 明确阶段、保留取消机会

整库导出／恢复预览增加快照、文件头／摘要、逐份事实、说明凭据、删除标记、容量和最后快照核对的阶段文案。逐份阶段报告当前序号与总数，删除标记按256条分段让出事件循环；不是虚构全局百分比，也不是估算剩余秒数。阶段开始前先显示状态并让出任务，再进入有界同步处理，用户可在阶段边界取消。

现有消息区域显示“可取消、尚未恢复”或“提交期间等待结果”；增加`aria-busy`可访问状态，不添加新布局。提交期间仍禁用取消，完成的提交不承诺因页面关闭撤销。导出成功只写“已请求下载”，不当作落盘验证。

单次JSON解析、规范化字符串或事实核验仍为主线程同步任务；本批没有Worker或流式JSON，不保证长同步片段内即时响应。当前100份约10秒的全库导出成本不因此消失，不包装成新一轮全面性能提升。

### 临时大对象按职责释放

- 整库导出仍完整核验每份源正文，但不再把所有已解压的完整回放存入文档Map；只有恢复预览需要为事实比较保留相应文档。
- 新增`discardBackupPreview`释放内存准备计划，不改数据库。取消、换文件、重新核对、成功恢复及离开组件时显式释放旧计划；即使读取迟到完成，也丢弃对应准备计划，不留下一份隐藏正文快照。
- 迟到导出在取消后不会请求下载。旧确认、事实／索引变化、容量、原子失败及删除保护保持原逻辑。

这是一轮资源生命周期整理，不声称GC已立即回收或峰值内存下降某个百分比。v49原生测量报告和旧HTML继续保留，不用本轮实现去改写历史数据。
