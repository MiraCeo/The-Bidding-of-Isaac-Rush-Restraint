# 浏览器存储与保存测量 v41

> 日期：2026-10-14。0.4.0开发预览第一步：只读诊断与真实浏览器容量／保存基线，为长期回放库选型提供依据；没有接入回放库、独立档案或成就。

## 一、正式界面

进度 → 存档与备份 → **浏览器存储与保存开销**，默认折叠，展开／刷新时显式读取当前来源的localStorage，最多扫描256条。区分当前经典、生存、档案、偏好、旧开发缓存及其他来源，按文本占用排序；旧格式只统计大小，不解析、迁移、删除或覆盖。未知来源不显示键名或原始值，读失败保留成功部分并标“部分／不可用”，不能把失败误当零占用。

同时显示包含键的UTF8字节和UTF16码元×2估算。两种口径不相加，不是实际磁盘占用，也不能据此保证剩余容量。下载无损压缩没有改变localStorage自动保存原JSON。

另读取navigator.storage.estimate的站点估算，明确它不是localStorage可用空间或上限。API缺失／拒绝时显示不可用，迟到结果在离开面板后丢弃。不请求持久存储权限，不在正式来源填满配额或运行测试写入。

经典／生存的原保存与启动读取函数增加被动总耗时记录：最多最近60次，本面板显示最近12次，仅在内存中，刷新程序后重置。不存种子、游戏／档案内容或文件正文；计时API或结果分类失败不改变原返回值、异常和保存顺序。包括序列化／验证与同步存储调用，不等于纯磁盘耗时、布局绘制或帧率；缓存命中、读取空存档也会记录操作完成，部分归档失败记操作未完成，以原保存状态提示为准。

实现：web/lib/ui/persistence-metrics.ts、storage-inspection.ts、components/game/storage-diagnostics.tsx。游戏规则、RNG、AI、最高难度、草稿、v5文件、容器1、档案1与存储键均未改。

## 二、原生浏览器隔离测量

只在自己的空白HTTP来源127.0.0.1:3027运行研究页面，不接触用户其他端口的真实存档。页面构建为生产minify，不导入到正式游戏。来源已有任意数据时拒绝探测，不通过清空数据来制造“空白”。

容量探测只使用新建的专属随机前缀测试键：有界到6Mi个码元，二分精度32Ki个码元，分别写ASCII与中文；停止／结束清理自己仍拥有的值，键被其他写入替换时不删除。不是正式游戏自动执行的功能。单位必须保持码元／文本字节分离，不能按某个浏览器结果给所有用户承诺固定上限。

输入使用0.3.10已验证的v5模拟文件：经典以撒20261013的第2房草稿及15房终局备份；生存以撒3最高的第2房草稿及7层35房终局备份；另生存游魂42的较小最近回放用于真实配额失败对照。

每种操作预热1次、测5次，逐次异步让出页面。原生写入的原JSON附加不同数量空格避免相同值被浏览器直接跳过；正式保存保持原缓存行为，因此经典进行中保存的结果包含缓存命中。校验前后权威游戏规范JSON不变、无损压缩原文逐字一致，不将这些操作当作额外的真人／AI行动。

### 本机结果：Windows，Chrome155，HTTP隔离来源

ASCII与“存”分别8次探测，单条值成功区间下界**5,210,112码元**，首次拒绝样本**5,242,880码元**；间距32,768。对应ASCII UTF8约5.21MB，中文UTF8约15.63MB，两者UTF16估算均约10.42MB。包含测试键后写入失败；这说明此浏览器测得的码元边界不能直接当作下载文件UTF8字节上限，不是通用容量承诺。

下表为5次测量中位ms：

|---|---|---|---|---|---|---|---|

|经典15房终局|51.70|190.40|1.00|52.10|不做当前局读取|18.30|15.00|

**测量对象区别：**经典进行中编码／解析是检查点，经典终局是完整备份；生存进行中是检查点，生存终局“编码／构建”是实际完整事实回放的快照／校验／编码，“严格解析”是完整备份，而“正式读取”只读检查点。终局压缩／解压和原生setItem采用完整备份文本。列之间不能当成同一对象的流水线耗时相加。同步API返回不证明操作系统已落盘，未测浏览器绘制与帧率。

生存终局正式自动存储本批共两条原JSON：UTF8约1,811,032字节、UTF16估算3,568,152字节（含研究前缀键）；完整回放是主要开销。手动文件压缩有帮助，但不会降低当前自动存储文本占用。

## 四、下一步结论

第一批容量／开销基线足以说明：**长期完整回放不应仅把更多原JSON继续堆进当前localStorage键。**下一批先将大事实与续玩隔离，设计有容量上限、稳定索引、导入／导出和真实删除语义的回放库；存储方案须继续覆盖不可用环境及失败不阻断检查点。优先避免终局重复事实构建／归档开销，但不删评分／随机／淘汰事实换速度。

还未完成：其他浏览器／低性能设备／直接file容量与完整实玩、回放绘制／交互性能、原生下载落盘验收、长期回放库、独立档案备份及进度统计。诊断和单来源测量不是这些功能的完成证明。

正式生产包诊断也已验收：七层测试存档共4条，UTF8约1.73MiB／UTF16估算3.40MiB；同一来源站点APIusage=0、quota=10GiB，界面没有把它当作localStorage为空或可用10GiB。刷新只读诊断后终局与页面刷新恢复不变。全量1135通过／14报告默认跳过，后续15项及4项界面／版本复验通过，类型／lint和两构建通过。最终HTML0.4.0-e8f89cc5ebed，1,121,474字节，SHA256 `c7535cbda6677fb4c454e7561f178c590278a3f4b149e5c5387cdc6991ca2294`。当前改动未提交，过程与限制见 [0.4阶段实施记录](../../记录/0.4阶段实施记录.md)。
