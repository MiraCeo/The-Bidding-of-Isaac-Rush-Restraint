# 大库原生性能测量与核验复用 v49

日期：2026-10-14；本批0.4.8，保留0.4.7整库功能。按用户要求，测量和回归完成后与上一批整库更新一起commit，不push。

## 一、方法与语料

使用正式`ReplayLibrary`、整库文件校验与`ReplayLibraryPanel`，在独立空HTTP来源的原生IndexedDB中顺序运行，不用fake-indexeddb时长当浏览器性能。开始前拒绝已有localStorage或数据库的来源，所有研究库留存，不清除既有资料，不运行AI或登记玩家成绩，不执行原生下载。

语料为100个真正按正式规则运行的不同种子模拟局，经典／生存各50，五角色与四档生存难度；含14个35房长局，不是修改回放ID的复制品。经典全部15房，生存15／20／25／30／35房混合；`roomDistribution`合并两模式后15房52局、20房4局、25房16局、30房14局、35房14局。元时间固定为测试值，不能冒充玩家实际保存时间。

`web/work/large-library-performance/corpus.json` 9,941,722字节，SHA256 `19974d00818374efd1ac6b730b0a45bb729c1f4962388ee3c73f4f13cdf6c35d`。正文实际已存7,913,906字节，解压后各份原文合计69,503,132字节；后者不是当前库已存文本额度或峰值内存。每份仍受8 MiB限制，100份未超过64 MiB应用上限。

- 主库按10→50→100逐步新增，记录单次新增分布；这种人口装填没有预热，且三阶段新增样本数分别10／40／50，不混称同一笔写入的重复试验。
- 读取类3次计时＋1次预热；35房分解5次＋1次预热；空库预览／提交使用3个不同新目标库，含冷启动。保留全部样本、经验中位／P95／最大值。
- 测轻索引、35房读取、已准备回放重复入库、原生三store快照、容器核验、完整导出、重复预览、空库预览及原子提交；分解35房的正文SHA、解压、事实解析、事实身份SHA、gzip与正式准备。
- 挂载真正生产表格并测数据就绪DOM、角色筛选／返回的DOM提交。不是布局绘制时长、FPS或低性能真机验收。
- 删除标记矩阵0／1000／8192：半数旧原键标记，半数含真实样本的30项说明凭据；键为合成研究键，不冒充真实删除历史，也不宣称覆盖600项凭据的最坏构筑。
- 采样Chromium JS堆、50ms计时器迟延和Long Task；包括设置与校验全过程，不是严格峰值／总进程内存或帧率。未强制GC、未固定系统其他软件负载，前后单机数据不推广为所有用户保证。

研究页由`web/scripts/build-large-library-study.mjs`构建，语料由opt-in `GENERATE_LARGE_LIBRARY_CORPUS=1`研究测试生成。保留语料SHA、测量／UI／解析代码SHA、提交来源和dirty状态。基线源码另存`.ts.txt`，避免研究证据被tsconfig误当工程源码；不修改类型检查范围。

## 三、本轮局部优化边界

1. **只在同一次预览复用已验证的事实。**本机原正文字符串与输入原正文完全相同、整个索引（含时间／来源／扩展字段）规范JSON相同，才复用已验证输入文档；否则继续解压、摘要和事实全验。不建立跨请求／跨数据库快照缓存。
2. **同一已验证文档对象的说明凭据只算一次。**仍保留原字节与限定浮点邻域，不通过粗略键／哈希猜测另一正文相同。
3. **标记同键查重改为Set。**优先级仍是保留已有原标记；已确定重复并保留存活原件时，不再多扫删除保护，因为这不会改变原重复优先语义。

所有结构／元数据边界、输入事实核验、旧／新标记保留、说明600项与原邻域限制、容量、提交前同事务三store比较和失败原子性均不省略。原文不同、任意索引字段变化、损坏资料或预览后库变化仍拒绝／重验。
