# 逐房回放 v2

> 已归档：0.2.8时期的v2说明；现行协议见 [逐房回放v3](../0.2/逐房回放_v3.md)。

> 日期：2026-10-12。应用0.2.8；电脑端三视图不变，设置入口已统一并按状态去重；只支持v2对局协议。旧快照格式说明仅作 [历史资料](./逐房回放_v1.md)。不改变实际结算或正式AI，不做自动播放或分支对局。

## 一、入口

设置页“对局与记录”按当前／上一局／文件回放分别显示可用操作，同一局实际结果去重。进行中点击“查看回放”，已结束或最近记录点击“查看对局”；回放页可导出。外部文件由统一“导入文件”识别，先预览，再明确“打开回放”，不再读完自动跳页。具体情境见 [入口说明](../0.2/设置数据入口与状态_v1.md)。

回放只读，不替换当前比赛、草稿或玩家档案；完整迁移使用 [完整备份](./构筑与存档_v2.md)。刷新后不会把已结束比赛作为活动检查点恢复。

只显示已经结算的房间。未知道具仅在原房间已结算后展示，未来房间和未提交行动不进入回放。

## 二、结果优先的电脑端布局

- 顶部只保留角色、完成状态、记录数量与导出按钮；长对局ID、开始构建和规则指纹移入默认折叠的档案详情。
- 左侧窄目录按层分组，显示所选玩家的层合计、房型、房分和获奖份数，独立滚动；不再用十五张大卡占满首屏。
- 右侧工具栏切换房间和玩家；复制定位是小按钮，定位／构建详情默认折叠，剪贴板失败时展开方便手动复制。
- 右侧拆为**房间复盘／整局概览／全场明细**，切换只影响查看视图，不写入对局或调用AI。
- 房间复盘首屏三块摘要突出最终房分、资金变化和实际获奖；资金拆开扣款、返款及其他结算变化，入房／换层资金重置单列，不把重置当作收益。
- 接着显示计分链：行动小计 → 综合倍率／清零 → 原始房分 → 追溯追加 → 最终房分。使用保存的明细，不重新掷骰或重算分数。
- 两目标资格卡串联实际行动 → 资格 → 发放，并用不同颜色标明获得／未发放／扰乱占位／未获资格；毁奖／复制原因直接列在对应目标下，与市场图并列。
- 市场位置图按A／B展示每个实际行动；双行动画两个点，观望不伪造报价。圆点竞拍、方点扰乱、亮色所选玩家、蓝带合作区、金线实际高价占位边界。文字数值和原始行动表仍可核对，不仅依靠颜色。
- 关键事件采用入房 → 提交结算的纵向时间线，保留原顺序与关联转移双方；带道具来源的追溯积分不会被普通积分事件过滤隐藏。获取道具显示名称而不是ID，效果来源与被影响道具分开。
- 计分细项和库存实例默认折叠，库存先按道具类型聚合。整局概览展示累计分、扣款／返款、获奖份数、积分与资金轨迹；点击轨迹返回对应房间，王冠倍率只在终局显示。
- 全场明细采用20人行动／资金／积分／获奖表格，点击玩家返回其个人复盘；全场资格改为表格核对，不再串成大段人名。房间、玩家和当前真实对局状态彼此独立。

终局表保留原记录排序，精确同分显示并列名次。返回游戏或Esc只返回当前真实阶段，不结算、推进或修改秘密草稿。移动端没有列为本轮适配或验收范围。

## 三、无损差分文件

格式名称仍为`the-bidding-of-isaac-replay`，只读取／导出版本2；最大8 MiB。v1和未知版本在调用当前算法前拒绝，不自动迁移。v2内部编码仍为`player-deltas-1`：

1. 全员初始状态保存一次；道具实例表保存实例ID、道具ID及获得顺序，库存引用实例ID。
2. 每房保存入房变化与结算后变化，不反复复制20人的全量库存；上一房结束状态由上一条结果取得。
3. 每层第一房保留入房检查点，便于核对边界和跳转。
4. 实际真人／AI行动、市场／计分等价、基准线、资格、毁奖／复制／赎回、原始／追溯／最终积分、事件原文及终局全部保留。
5. 解码只还原记录，不调用AI、结算或随机数；已有v2房间反馈定位不因新界面改变。

没有将文件改成难读的单字母字段或有损小数；当前不引入压缩文件依赖。事件原句暂保留以维护旧规则核验和定位，可见文字在显示层转换。进一步事件模板化需独立设计迁移，不改写历史事实。

## 四、校验与旧文件

读取先检查格式、大小、规则及元数据，验证差分字典引用、玩家顺序、字段集合、层检查点和完整记录；未使用实例、额外／重复差分、篡改资金／行动／事件／积分／终局均拒绝。

同规则记录仍在独立临时会话核验最多十五房；页面展示通过核验的实际记录，切换房间不再调用算法。当前不支持跨规则版本迁移，不因v2有差分就使用新规则重新解释旧比赛。

轻量续玩文件不含原始整份回放；恢复出的历史标记`checkpoint-reconstruction`，保留已知构建和结果指纹。完整备份和独立v2回放保留原始`live`／历史重建来源；保留来源不表示还可以读取v1文件。
