# 逐房回放 v1

> 历史归档：0.2.6已改用差分文件与电脑端结果优先布局；本页保留原v1说明。现行见 [v2说明](../0.2/逐房回放_v3.md)。

> 更新日期：2026-10-11。T06最小可用回放已实现。只读逐房查看，不做自动播放、分支对局、撤销秘密提交或从历史房间恢复；正式规则、20人格参数与道具池不变。

## 一、入口与使用

打开 **设置 → 逐房回放**。

- **查看本局回放**：查看当前对局已经结算的房间。至少提交一房后启用；当前尚未提交的房间不进入记录。
- **导出回放 JSON**：下载独立回放文件，名称包含“回放”和对局标识。
- **读取回放 JSON**：读取并校验文件，然后打开只读页面。初始选角页也能使用，不要求先开始游戏。
- **查看已读取回放**：重新打开本会话之前读取的文件记录。

回放页保留原顶栏，不增加第五个主导航，不使用弹窗或缩小行动区。通过房间列表、上一房／下一房逐房切换；玩家选择器可查看真人或任一AI，事件可切换所选玩家／全场。

顶栏“游戏”、页尾“返回游戏”或Esc返回当前真实对局阶段。原选角或未提交报价保持不变；返回结算或终局也不会再结算。读取文件回放不会替换当前对局或写入其自动存档。

## 二、每房保存什么

真人提交并完成原引擎结算后，才追加一条独立快照：

| 内容 | 记录方式 |
| --- | --- |
| 定位与版本 | 对局种子、层／房间位置、本房构建、记录来源 |
| 入房阶段 | 原入房事件、提交前玩家状态；第二房起还保存上一房结束状态 |
| 实际行动 | 真人与19AI的完整行动、A／B顺序、金额；另存AI选择的行为名称 |
| 市场与资格 | 基准线、所有市场／计分等价、最高价与合作区占位、最终资格、赎回 |
| 实际结果 | 最终发放份数、毁奖／复制、返款、资金恢复、屏障消耗、道具实例 |
| 得分 | 每行动基础分与加算、实际计分取值、倍率／触发／清零、原始／追溯／最终房间分 |
| 结算后状态 | 全场资金、积分、完整库存、屏障和项圈检查状态 |

记录深拷贝，与继续游戏的状态分开；查看榜单、切换设置、返回游戏不会追加或修改记录。同一房间不重复记录。换层前后仍保留两侧快照，可分辨资金重置、利息与其他入房经济。

第一房不存在“上一房结束”快照，明确标为空；其角色资金发放及入房效果由入房事件与提交前快照说明，不伪造此前的房间。

### 随机结果口径

保存的是实际结算输出，不是重新抽取的演示结果：六面骰翻倍、永恒骰清零、超凡升天赎回、更多选择毁奖、尾巴毁奖／复制、项圈检查与实际恢复等，均由原触发、事件和前后状态呈现。

未触发的骰子效果可显示“未触发”；不会补造引擎未记录的原始随机浮点数、逐次掷骰画面或概率解释。普通倍率和条件清零也与随机触发分别注明。

## 三、查看界面

1. **档案信息**：角色、种子对应的对局标识、已记录房间数、部分／已结束状态、开始构建及规则版本。
2. **房间与玩家**：选择已结算房间及任一玩家；不会展示本局未来房间或当前秘密行动。
3. **本房摘要**：基准线、入房／结算资金、资金变化、原始＋追溯＝最终房分、累计分、库存与屏障变化。
4. **行动明细**：名义报价、实际扣款、市场等价、原始计分等价、实际计分取值、基础分、加算与乘算前小计。
5. **资格与发放**：两件道具、最高价和合作占位、资格来源及最终份数；原本未知的奖励只有在已结算的历史记录中公开。
6. **事件与效果**：入房与提交结算分列，查看实际触发和返款／毁奖／复制等结果。
7. **全场快照**：可展开20人资金、原始／追溯／最终房分、累计积分和获奖表；可展开所选玩家的结算后库存实例。
8. **终局**：完成后，最后一房显示保存的最终排行、累计分、王冠倍率和终局分，保持原局并列排序，不重新计算排序。

这是一份只读档案，没有提交、进入下一游戏房间或重新开始按钮。上一房／下一房仅移动查看位置。

## 四、如何反馈问题

回放页提供可选中文字的定位栏和“复制房间定位”，格式如：

```text
ISAAC-0000002a-jacob_esau-规则指纹/F1-R2#房间指纹
```

对局标识由种子、角色与规则指纹组成。房间指纹由实际行动、结果与事件产生，用于区分相同种子的不同玩家行动分支；界面样式更新不改变同一结果的定位。

反馈时携带：**回放JSON + 房间定位 + 查看玩家 + 具体显示或体验问题**。文件保留当时的结果与版本，能核对是显示遗漏、资格／结算逻辑还是已经记录的随机触发。剪贴板不可用时仍可手动选中定位文字复制。

## 五、文件校验与版本

- 格式：`the-bidding-of-isaac-replay`；版本：`1`；最大大小：**8 MiB**。
- 文件与存档格式不同。回放用于只读查看，不能作为存档载入继续游戏；存档通过原入口读取。
- 保存开始构建、每房构建、终局构建和导出构建。离线版本读取HTML真实的 `bidding-offline-build` 元数据；普通网页使用构建时源码指纹。
- 规则版本不兼容时，在执行当前算法前拒绝读取，不静默用新规则解释旧记录。当前不做跨规则迁移。
- 对兼容记录，在独立临时会话中核验至多十五房的实际真人记录，逐字段比较玩家／AI行动、随机结算、事件、状态和终局。页面读取通过校验的原始快照，查看时不再调用AI或结算。
- 错误JSON、超限文件、未来格式版本、缺失构建标识、错位／重复房间、被改写的资金、积分、道具、资格、AI行动或事件会拒绝读取；原对局与之前的有效文件回放保留。
- 文件读取期间离开设置页，会取消尚未完成的读取结果，不在后台把页面突然切回回放。

构建标识用于定位界面版本，规则兼容标识用于约束解释算法。完整性核验不是服务器签名，也不新增业务后端。

## 六、与T04／T05的关系

新对局记录随存档一起保存，自动恢复后可继续查看之前所有已结算房间。存档的最大大小同步扩大到8 MiB，以容纳逐房快照；格式仍为v1。

兼容的旧v1存档没有逐房档案时，利用其完整种子和已提交真人记录核验重建；注明“旧存档重建”，原构建注明“未记录”。之后新提交的房间按实际新构建记录。不能将重建结果冒充原始逐房录制版本。

读取外部回放只存于本次界面会话，不覆盖本局存档；刷新后可再次读取文件。本轮不建立长期回放库，不自动保留已清除／新开局之前的旧对局；保留旧局时先导出JSON。
