## 本地开发

```powershell
# 从仓库根进入前端目录
Set-Location -LiteralPath '.\web'
npm ci
npm run dev
```

开发页面默认[localhost:3000](http://localhost:3000)。AI和对局在浏览器运行，Vite不是业务后端。临时自动复验服务仅绑定127.0.0.1，验收后停止。

## 日常验证

在`web/`中顺序执行：

```powershell
npx --no-install tsc --noEmit
npm run lint:client
npm test -- --maxWorkers=4
npm run build
npm run build:offline
npm run verify:offline
```

- 类型检查、lint、规则／交互回归、构建与真实页面验证是不同证据。
- 报告型批量测试默认跳过；不要为了通过而关闭已有普通回归或放宽事实校验。
- CPU较重的完整回归与研究顺序运行，避免叠加；4 workers是当前验收的资源控制，不是游戏参数。
- 运行完整测试期间不改源码，防止部署测试核对源码指纹时混入中间状态。
- 证据放`web/work/`；TS源码快照用`.ts.txt`保留，避免被宽范围tsconfig当成项目源码。
- 本轮可用`node web/scripts/check-doc-links.mjs`从仓库根检查本地文档链接与归档JSON换行；也可从`web/`执行`node scripts/check-doc-links.mjs`。命令不验证远端URL或页内锚点。

## 网页与离线包

`npm run build`输出`web/dist/`。`npm run build:offline`输出`web/dist-offline/`的单文件HTML、带版本HTML、manifest和SHA256；旧带版本包保留，固定别名更新。

dist-offline按主号.次号（如0.2、0.3、0.4）保存旧系列归档，根目录仅保留当前开发系列与固定入口／当前元数据。切换开发系列时按此整理，不将补丁版本逐个分目录；历史包核验应递归枚举。仅整理目录不重新打包、不改固定入口正文或旧manifest来源，见[记录](../记录/dist-offline按版本系列归档整理.md)。

`npm run verify:offline`只读核对dist-offline的版本／归档／固定入口／manifest／SHA256／说明及当前文档入口，不构建、不打开浏览器、不写文件，也不将清单中的历史验证记录当作新门禁。

构建后核对应用版本／内容标识。普通build成功不是完整release／deployment门禁；manifest验证字段未填时不冒充门禁通过。直接file、实际下载落盘、恢复和HTTP视觉复验分别记录，见[离线构建](./离线HTML构建与验收.md)、[离线验收清单](./离线文件验收清单.md)及[最终流程复验](../记录/0.4完整流程复验与最终收口_v54.md)。

当前交付使用上方`npm run build:offline`。下列release／deployment脚本是历史或独立发布工具，不是0.5当前离线打包流程，也不应为了打包自动调用：

```powershell
npm run build:release
npm run build:deployment
npm run prepare:deployment
```

这些命令不会让云发布自动验收。CI／手动发布配置在`.github/workflows/`；具体范围见[发布准备](./云发布与分发准备_v1.md)。
