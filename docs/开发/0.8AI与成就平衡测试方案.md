# 0.8 AI与成就平衡：首批离线研究方案

日期：2026-10-20。用户要求开始测试AI及成就相关平衡。本轮研究当前0.8.0、schema8／catalogVersion7，先形成数据和建议，不直接修改AI、成就阈值或角色前置，不重建刚交付的0.8.0 HTML。

## 一、为什么不直接重跑旧研究

旧0.6.5的2250局工具只有经典原版＋生存4档，且对应条件收紧前schema7／catalog6。现在经典有显式classic-tiered-1四档，生存使用role-aware-1，最高保留原策略；需要重新记录实际策略身份、本金实扣、困难层证据以及真人实际参与范围。旧结果和目录保持，不改写为新版本结果。

研究扩展只在test-helper、受控报告测试和scripts中；旧函数不传新选项时保持原行为／输出形状，旧矩阵、种子和分析器不改。新增只读观察通过前后动作、成长上下文与终局指纹等价回归；正式客户端不导入这些研究模块。

## 二、预先固定的矩阵

| 阶段 | 设计 | 局数 |
| --- | --- | ---: |
| pilot | 1个种子×5角色×经典4档／生存4档×3种脚本 | 120 |
| main | 10个独立配对种子块×相同120格矩阵，每格真实累计10局档案 | 1200 |
| campaign | 3个新档种子块×3种脚本×经典最高／生存标准×20局，角色按真实解锁轮换 | 360 |

三组共1680局。pilot不并入主矩阵估计；主矩阵只有10个独立种子块，角色、档位、脚本之间是配对条件，不是1200名独立玩家。新档共18条20局路径，不据此给真人解锁时间作精确推断。固定角色矩阵可以控制已锁角色以覆盖条件，不表示新档UI已经能选该角色；campaign从以撒开始，只使用实际解锁角色。

脚本沿用均摊报价pace、公开信息强脚本public-ai、探索扰乱explore，不注入道具、不改变收入、规则或AI参数。public-ai真人槽保持其原强策略，不跟随对手档位一起削弱；三种脚本都不是人类遥测。模式／档位改变后路径可能自然分叉，固定的是策略函数、种子及初始世界，不是强行让后续动作／随机结果逐房一致。

种子公式：`(0x08010000 + Math.imul(index + 1, 104729)) >>> 0`。pilot索引0，main为100～109，campaign为1000～1059；与旧0x65100000研究分开。每组的相同种子跨条件配对；相同模式／角色／脚本的四档先验证初始名册、首层奖励及AI静态档案指纹相同。生存未来楼层按正式逻辑生成，不伪称已经冻结整局未来世界。

## 三、观察与统计口径

### AI

- 真实正式名次、经典最终分、生存存活／淘汰层及真人参与房数；经典最高分含并列与唯一正式排序位置分开。
- AI逐玩家回合的合法性、实际现金预算、观望率、零现金率、双行动率、扰乱行动占比与实际花费比例；双行动不冒充两名玩家，分母分别注明。
- 真人参与期间与真人淘汰后的AI续赛分别累计，后者不喂回真人成长。
- 按角色、流派描述实际终局，不把重复配对槽位当独立玩家，也不从人格共现／角色均值直接推断因果或批准平衡。
- 同种子四档对照正式名次差、积分差、存活／参与房间差；不要求每局都随难度单调，也不用累计分跨生存状态重新排序。

### 成就

- 全117枚仍通过真实成长上下文、生产档案求值及严格凭据去重；不手工累加已获布尔，不从回放读取补奖。
- 固定角色10局与正常解锁轮换20局分开记录；首获局数只统计已命中路径，未达成单列截尾，缺失不填0。角色／模式／档位硬门槛不适用不能算失败。
- 单局率只作描述，累计成就优先看档案路径；各显神通不输出单局达成率。难度金阶、游魂与雅阁限定必须使用正确分母。
- 道具持有／实际机会与真人房数、BOSS资格／交付、层结算通过／最低存活次数单列，不把所有房间当触发机会。
- 优先复核厚积薄发、吊车尾、已收紧后的孤注一掷，以及与已有金额／全押系列的重叠；不直接套用旧93.1%或1／10／30建议。

## 四、可复验运行及资料保护

在web目录顺序运行，CPU较重研究与全量测试不叠加：

```powershell
node scripts/run-balance-study.mjs pilot
node scripts/run-balance-study.mjs main
node scripts/run-balance-study.mjs campaign
node scripts/analyze-balance-study.mjs <pilot绝对目录> <main绝对目录> <campaign绝对目录>
```

每次独立分配`web/work/0.8/balance-study/<用途>-随机串`，marker保存固定计划和完整源码SHA256；输出排他写入，不接受旧目录覆盖。每局保留正式成长上下文、指纹和机会见证，每批保留真实累计档案；分析核对1680份上下文、根身份、档案哈希、策略身份、组间种子不重叠及四档初始世界。

来源允许当前未提交工作树，但必须如实记录commit＋dirty及逐文件SHA256，不把0.8.0打包时的旧源码指纹冒充研究来源。正式规则／存储／UI、138份旧新版本HTML及原研究资料不修改。缺能力或保存预算错误应原样报告，不以放宽限制取得研究结果。

本批不访问浏览器、真实玩家档案或网络，不运行新发布／部署，不把脚本模拟当成手感、像素或真实文件验收；首批完成后另写[研究结果](../记录/0.8AI与成就平衡首轮研究.md)，把证据、候选与未确认项分开。
