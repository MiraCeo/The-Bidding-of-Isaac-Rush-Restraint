## 二、实现方式

普通开发和网页构建保持原样。新增构建脚本使用现有 Vite 配置中的 React、Tailwind 与别名，通过独立的生产 IIFE 构建将游戏和 React 编译进单一普通脚本，再与 CSS、SVG图标一起嵌入 HTML。

| 文件 | 职责 |
| --- | --- |
| `web/scripts/build-offline.mjs` | 内存构建正式 `main.tsx`、读取页面与图标、生成单文件产物 |
| `web/scripts/offline-html.mjs` | 资源门禁、HTML内嵌、原始文本边界转义、构建标识与离线资源策略 |
| `web/scripts/offline-html.test.mjs` | 单文件格式、外链拒绝、边界转义和产物契约测试 |
| `web/scripts/offline-build.test.mjs` | 实际项目生产构建集成测试，不改写普通 `dist` |

具体处理：

1. 不使用外链模块脚本；依赖随 IIFE 打包，不依赖浏览器读取其他 JS 文件。
2. 显式固定 React 生产环境，避免保留浏览器不存在的 `process.env`。
3. CSS内嵌为 `style`，favicon内嵌为数据 URL，不复制分享预览图片。
4. 移除线上分享元数据，拒绝未内嵌产物、CSS外链和页面资源外链。
5. 为 JS/CSS 的 HTML结束标签做转义，避免内容意外截断内嵌脚本或样式。
6. 添加仅离线产物使用的资源策略，禁止 HTTP连接与外部脚本、样式、图片、字体等加载。
7. 所有检查通过后才写入输出文件；不清空或改写普通 `dist`，也不修改源 `index.html`。

生成目录加入 Git 和 Docker 忽略配置。离线构建本身没有新增 npm 依赖、业务后端、Service Worker 或桌面安装程序。后续T02／T03新增的 `happy-dom` 仅用于开发测试，不进入离线运行包。

以后新增图片或字体时，应作为源码资源导入，让构建器内嵌；不要直接依赖 `/public文件名` 或 CDN路径。新增网络功能时需要分别定义在线与离线行为，并补充验收，不能仅凭导出成功认为新功能支持离线。

实现依据：[Vite JavaScript构建API](https://vite.dev/guide/api-javascript.html)、[Vite库模式与CSS处理](https://vite.dev/guide/build.html#library-mode)。
