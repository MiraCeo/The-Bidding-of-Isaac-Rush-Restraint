程序是内嵌脚本／样式／资源的单文件HTML，不需要业务后端，也不需要发送普通网页`dist/index.html`。用户可自行打开固定HTML或复制带版本HTML；本轮没有打开浏览器或执行试玩／真实文件往返。

当前version／buildId／大小／SHA256以本次清单为准，使用`npm run verify:offline`核对；不要把历史记录中的构建标识当成每次重建后的最新文件。固定入口和当前带版本文件应逐字节相同。构建源码／时间以本次`build-manifest.json`为准，不将此前releases清单移植或改名冒充新构建。

此前目录纠正批次只更新固定入口与配套清单／说明，并保留所有旧带版本HTML；本轮另有长期账本源码优化，见下方专项记录。旧固定入口和配套元数据在更新前备份到`web/work/v050-dist-offline-correction/prior-dist-offline/`。误放在releases中的本次0.5目录仅移入同一work证据目录留档，不改动0.2历史。

## 二、功能入口

PC顶栏统一品牌、五项导航和右侧小版本；层房／资金等放入上下文行，不用“主菜单·版本”表示当前位置。排行／进度／设置／规则的返回操作位于标题右侧，主菜单来源明确返回主菜单；报价、草稿及结果不因切页重新计算。

- 主菜单→经典模式／生存模式：选择角色并开局；默认仅以撒。
- 进度→成就：六类107枚徽章／57卡紧凑列表，名称／编号搜索、分类／完成状态筛选、最近达成／进度排序；自动或1～3列布局，窄容器以可读性优先。点击卡片打开完整条件、特殊判定、真实进度、时间与角色关联；单局型展示已记录的单局最高值，不冒充当前连续数。
- 列数选择仅存本机独立显示偏好，不在档案备份中；读取不写、失败仅影响偏好保存。角色前置可直接点开详情，不需清除当前列表筛选。新增六项为B05／B06／E06／E07／E08／F06，纯收藏、不改角色前置。详情含解锁后收藏札记，通用统计规则可单独打开。
- 0.5.4徽章分铜／银／金（21／11／4），可以按等级筛选；仍36枚、不新增门槛。屡战屡败／祸不单行／逃出生天未达成时列表显示问号，不显示真实名称或进度；可按编号查找、点击详情查看真实条件，达成后恢复专属展示。原已达成状态与时间不变，不需重新完成。
- 0.5.5全部成就按分类标题／分割线分段，各类独立网格，最近达成／进度在分类内排序；左侧徽章在未达成时也可识别铜银金，达成后提亮。两模式保存成功后右上方显示徽章／等级／札记通知，同局未读合并、手动关闭，不自动计时消失，也不重载补弹。
- 0.5.6最高价1／10／50、利息100／1000／5000、生存完成1／5／15共三组单卡三级；经典完成1／5／20为独立三卡。各级有独立ID／时间／札记，部分完成显示1／3或2／3，按等级／状态／子ID过滤必须命中同一枚徽章。新增C09／F12隐藏，原列表／提示行为保持。
- 新累计门槛继承可靠账本，首次新正式事件成功保存后确认新等级，不改旧银时间；新同局复合只认启用后同父分支，D10不补造旧节省金额。完成局数按原正式身份去重，相同身份重开和同根分支不多计；生存淘汰也须正式终局才计完成。

- 选角页或进度→成就→一键解锁全部角色：只改角色权限，不完成成就或增加统计进度。
- 进度→存档与备份：续玩、回放、本局完整备份及独立玩家档案的导出／读取与确认。
- 进度→对局记录→长期完整回放库：完整回放及整库备份／恢复，不等同最近200条轻量完成历史。
- 设置／规则：显示偏好、版本说明、规则和独立教学。

游魂需要“非将军之过＋屡败屡战I（5局正式终局排名第6及以后）”，旧成就派生权限清理后需重新达成，手动授权保留；阿撒泻勒需要“厚积薄发＋硫磺火？”；伊甸需要“神秘礼物”；雅阁和以扫需要“我全都要”。已有合法旧局可使用原角色继续，教学和AI不受新局选角权限限制。

## 三、资料与兼容边界

- 存档保存在浏览器来源中，不写入HTML。复制／移动程序不等于迁移玩家资料，也不保证不同路径、协议或浏览器共享自动存储。
- 旧资料需由用户另行导出，再在新程序的对应入口读取；只读取当前v5对局，不恢复v2／v3／v4。原JSON与压缩容器1仍按既有入口识别。
- 新读取器可读缺少growth的旧v5，带growth1的新检查点不能交给旧0.4读取器；档案正文1、独立档案文件1、整库备份1是不同协议。
- 本次长期账本优化保留全部旧凭据；新增写入达到256条后转紧凑schema2，读取／重复保存不迁移。旧0.5程序不能读取schema2，包含它的档案或配套备份须用新程序；模块名尾缀不代表内部版本。紧凑最多16384条，仍受896KiB模块／1MiB整档限制，不是无限终身容量；见[技术说明](../技术/0.5成长账本紧凑存储与核验复用.md)。
- 0.5.3新增六项不追溯旧0.5历史／已结算局；旧局仅继续游玩后的新结算可贡献，新扩展使用schema3／catalogVersion2和growth.expansionFrom。旧schema1／2可读，旧节点key／时间保持；早期程序不能读取新扩展时明确拒绝，字节和条数预算不增加。
- 0.5.6新事实使用模块内部schema4／catalogVersion3与growth.milestonesFrom；旧schema1／2／3严格读取，只读不迁移。新格式含激活位置／时间与逐阶段新事实标记，旧程序不支持时明确拒绝；预算不增加。
- 0.5.8新增schema6／catalogVersion5及growth.cfFrom，原v5外层和存储键不变；新增三项组／行动数量，不把缺失的旧布尔猜成份数，准确计数继续继承，新增等级经新正式事实保存后确认。旧数据完全清理与全局编号重排另列TODO，当前不会自动清档。
- 0.5.7新增schema5／catalog4及growth.revisionsFrom；旧schema1～4严格读取，普通浏览／重复不迁移。可靠计数继承，新增等级经新事实保存确认；旧游魂权限保留，新失败对局只认真实最终排名。模块／整档预算保持，不增新存储键。
- 不依据0.4历史补发成就；旧预留解锁字段不作为0.5权限。正常重载保留合法0.5权限，明确恢复更早档案允许成就、进度和角色权限回到快照，不自动合并被替换成果。
- 预览、只读回放、重复恢复不额外发奖；完整备份默认仅载入局，替换档案需明确确认。独立档案不包含续玩位置、完整库或设置。
- 成长保存需要Web Locks协调；缺能力时保留待处理并提示，不显示虚假的已入账。gzip读取受浏览器解压能力约束。
- 保存失败区分检查点与成长／配套状态；原资料保留并可重试。要保留未保存局时先按界面导出，不以重新选角代替备份。
