更新：2026-10-18。适用于 `D:\The Bidding of Isaac` 的本地HTML视觉核对。用户已明确要求记录并复用此方法；新任务仍按其实际授权范围操作。

## 一、已验证的方法

使用 **Playwright＋已安装的Edge独立无头实例**。本机配套Chromium二进制缺失，但 `chromium.launch({headless:true,channel:'msedge'})` 已成功，不必因此下载或安装新浏览器。

- 内置浏览器控制入口禁用不代表所有本地渲染测试都不可用；分别检查实际可用能力，不改Work／浏览器权限、不接管用户现有浏览器。
- 使用 `browser.newContext()` 临时隔离上下文，不用持久化profile、现有cookies或个人存档。仅在这个测试上下文内选角、开始和操作。
- 离线HTML直接通过 `pathToFileURL()` 打开，阻止HTTP(S)请求，确认没有外部资源依赖；需要开发态时只使用明确授权的本地测试地址，并按实际依赖调整请求范围。
- 真实网页渲染后等待字体和目标界面就绪，先截图，再通过 `view_image` 实际查看。只输出DOM／截图文件名不能称视觉检查已完成。
- 所有图像、脚本、几何数据放入本机忽略目录 `web/work/0.7/visual-acceptance-20261018/` 或新日期子目录；保留旧证据，不混入发行HTML或玩家正式存档。

## 三、最小截图步骤

从仓库根目录执行Node脚本，核心流程如下（本机模块路径来自上一步，不加入项目生产依赖）：

```javascript
const { chromium } = require('C:/Users/12782/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright');
const { pathToFileURL } = require('node:url');
const path = require('node:path');
const fs = require('node:fs');
(async () => {
  const out = path.resolve('web/work/visual-qa', new Date().toISOString().replace(/[:.]/g, '-'));
  fs.mkdirSync(out, { recursive: true });
  const browser = await chromium.launch({ headless: true, channel: 'msedge' });
  try {
    const context = await browser.newContext({
      viewport: { width: 1440, height: 900 },
      deviceScaleFactor: 1, locale: 'zh-CN', reducedMotion: 'reduce',
    });
    await context.route(/^https?:\/\//, route => route.abort());
    const page = await context.newPage();
    const errors = [];
    page.on('pageerror', error => errors.push(error.message));
    await page.goto(pathToFileURL(path.resolve('web/dist-offline/以撒的竞合.html')).href,
      { waitUntil: 'load' });
    await page.evaluate(() => document.fonts.ready);
    await page.getByRole('button', { name: '经典模式', exact: true }).waitFor();
    const screenshot = path.join(out, 'main-menu-1440.png');
    await page.screenshot({ path: screenshot, fullPage: false });
    console.log(JSON.stringify({ screenshot, browser: browser.version(), errors }));
    if (errors.length) throw Error('页面运行错误：' + errors.join('; '));
  } finally {
    await browser.close();
  }
})().catch(error => { console.error(error); process.exitCode = 1; });
```

然后对生成的绝对图像路径调用 `view_image`。切换页面用真实按钮／标签操作，以实际DOM和代码确认选择器；使用 `setViewportSize` 分别捕获1440×900、900×800及本批约定宽度。需要观察整页时另存 `fullPage:true`，但不能只看缩小后的整页而漏掉实际首屏密度。

现有完整探针：`web/work/0.7/visual-acceptance-20261018/ranking-probe.cjs`，从仓库根执行 `node web/work/0.7/visual-acceptance-20261018/ranking-probe.cjs`。这个探针是本机证据、没有提交Git；上面的最小流程用于在证据目录不存在时重建通路。

## 四、如何验收与记录

1. 固定应用版本／buildId／HTML SHA-256，区分当前实际产物与未打包源码。
2. 截图→查看→定位问题→改代码→构建或本地开发态更新→再次截图。相同场景使用可重复种子／同一临时测试数据；对照不同宽度不要顺便改变对局或用户存储。
3. 记录页宽是否溢出、页面与表内各自高度、表头／数值对齐、固定列与焦点描边、滚动后身份是否可辨、操作是否在首屏可见。页面无异常不等于视觉美观。
4. 定位本人、切换页签、键盘焦点与精度设置通过真实浏览器操作核对，不只检查DOM属性存在。
5. 明确已查看的截图与未覆盖场景。此次通路探针只覆盖主菜单、经典首房、公开积分／资金榜和本人定位，不自动覆盖争夺／生存／终局／长名单。
6. 直接file打开的截图仅证明这一部分；真实下载落盘／导入往返、多页竞争、物理配额等继续独立验收。
