# 构筑、续玩检查点与玩家档案 v2

> 已归档：0.2.8时期的v2说明；现行协议见 [构筑与存档v3](../构筑与存档_v3.md)。

> 日期：2026-10-12。应用0.2.8；存档／回放只支持v2，不读取或迁移v1。已有v2数据、玩家档案扩展位、正式规则与随机派生不变。设置入口已按状态整理，见 [具体排布与流程](../设置数据入口与状态_v1.md)。

## 一、三类数据各司其职

| 数据 | 职责 | 本轮保存内容 |
| --- | --- | --- |
| 玩家档案 | 跨对局的长期进度 | 角色解锁条件记录、成就进度、累计统计、独立模块扩展位，以及最近200条完成对局索引 |
| 续玩检查点 | 继续未完成比赛 | 当前20人状态、AI档案与必要历史、房间计划、阶段、草稿、真人提交记录和历史定位元数据 |
| 对局回放 | 查看实际已发生结果 | 独立初始状态、房间状态差分、库存实例表、层检查点、实际行动／资格／事件／得分与终局 |

玩家档案有独立格式和版本，不属于规则指纹的一部分。`progression.characterUnlocks`预留解锁时间和条件ID；`achievements`预留进度及可为空的达成时间；`statistics`保存具名统计；`modules`用于命名空间扩展。未来条件、成就和模块ID不要求出现在当前目录中，读写原样保留。当前不执行解锁条件、不限制五角色选择、不发放成就，也不提前建设科技树。未来接入须另定义条件和模块迁移。

历史索引不是长期完整回放库。当前浏览器额外保留**最近完成的一局**，更早的完整回放请导出文件；索引最多保留200条，不据其长度伪造终身胜场。新开局不清除玩家档案和最近完成的回放。

## 二、构筑展示保持原样

顶栏角色名与房间状态胶囊进入独立构筑页，不挤占A／B操作空间；返回保留草稿。按道具ID展示完整库存、真实剩余屏障、双行动资格、扣款／市场／积分系数和终局王冠倍率；非叠加道具仍保留所有实例。竞拍／扰乱切换与四份报价草稿不变。未知奖励与未来房间不进入构筑或回放展示。

## 三、文件操作

在 **设置 → 对局与记录／数据管理** 使用：

1. **导出存档**：只在进行中显示，保存轻量v2检查点及草稿；已结束只提供回放导出。兼容规则下核验恢复，重建来源和已知构建／定位保留。
2. **完整备份 → 核对范围 → 导出完整备份**：一份检查点、一份差分回放、一份本机玩家档案，不重复内嵌；有当前局备份当前局，首页可备份最近完成的一局。
3. **导入文件 → 选择文件 → 核对用途 → 载入这局／打开回放**：统一识别v2检查点、回放与完整备份。选择文件、取消和失败不替换当前数据。

完整备份默认只载入对局与原回放，保留本机玩家进度；显式勾选“同时恢复文件中的玩家进度”才替换档案。档案损坏时不拿空档案冒充原数据，备份导出暂禁用；仍可导出存档／回放，或显式恢复有效备份中的档案。

HTML仍是程序，JSON是数据，文件保存不改写HTML。导出为本地下载，无网络请求。已结束对局不显示续玩导出；可导出回放或完整备份，自动续玩不将已结束比赛作为活动检查点。

## 四、自动保存与生命周期

| 浏览器键 | 用途 |
| --- | --- |
| `bidding-game-save-v1` | 历史键名保留，避免丢失已写入的v2；只接受v2活动检查点，不迁移v1 |
| `bidding-game-draft-v2` | 轻量草稿及对应检查点令牌 |
| `bidding-active-replay-v2` | 当前对局独立差分回放 |
| `bidding-last-completed-v2` | 最近完成对局的独立回放 |
| `bidding-player-profile-v1` | 独立可扩展玩家档案 |
| `bidding-ui-preferences-v1` | 原显示偏好，与档案／对局无关 |

- 草稿变化只更新草稿小记录，不重写当前状态或整局回放。正式游戏状态变化更新检查点；回放变化后才更新独立回放。
- 草稿令牌必须对应当前检查点，旧对局或旧阶段草稿不能套到新状态上。
- 同规则完整性核验发生在独立临时状态，最多十五房；不在当前局再次发放、返款、消耗屏障或重抽随机结果。
- 独立回放损坏／提交不同步时，有效检查点仍可恢复，明确提示“核验重建”；不因回放写入失败把有效续玩检查点作废。
- 完成对局先写完成回放与玩家索引，成功后清除活动检查点、草稿及活动回放副本。重复挂载／读取同一结果不会重复登记索引。
- 任一归档／档案写入失败时不提前清除活动检查点；自动存储失败不阻止游玩或手动导出。
- 完成后刷新返回首页；最近对局行的“查看对局”只打开回放，不复活比赛。游戏页“重新选角”需确认，保留玩家档案及最近完成回放；放弃未完成比赛前可导出存档。

仍使用本地浏览器存储，没有云存档或实时多副本同步。页面地址、浏览器或存储可用性改变时，通过JSON迁移，不保证file://不同地址自动共享数据。

## 五、格式与扩展边界

存档格式名称仍为`the-bidding-of-isaac-save`，只支持版本2，文件上限8 MiB。v2用`kind: checkpoint | backup`区分用途。已删除v1编解码分支与旧格式重建入口；v1或未知版本在运行当前算法前拒绝，不自动清除不可读原记录。已有v2中的已知构建与历史来源标记保留，不因原构建较早就拒绝有效v2文件。

玩家档案仍为独立v1格式，与“对局存档v1”不是同一协议；显示偏好和`player-deltas-1`编码标识也不随本次决定改号。解锁、成就及扩展模块不会因取消旧对局协议而清空。

检查点不再保存可核验重建的AI诊断输出、待展示行动副本和整局快照；保留当前结算、玩家／AI状态及必要输入。当前随机流按种子与房间派生，未修改算法，也不虚构一个连续PRNG内部状态。

规则兼容标识仍为`20-personality-client-1-818e3e55`。文件格式升级不等于游戏规则升级；未来改变算法、经济、随机流或正式配置仍需单独更新规则版本并制定迁移，不能用新规则静默重跑旧局。玩家档案的进度模块独立演进，新增解锁／成就不应迫使整个历史回放格式一起升级。
